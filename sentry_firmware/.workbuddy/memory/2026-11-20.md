## 新增:tools/rtt_log.py(RTT 连续落盘)

- 固件无文件系统 → "存 .log" 只能 PC 侧搬。脚本路径 `tools/rtt_log.py`,输出 `log/YYYYMMDD_HHMMSS.log`。
- 会话边界:起点 = `[CMD] reinstate, robot ready`(解锁沿),终点 = 下电(连续 3 次读失败)或 Ctrl-C。
- 关键机制:**常驻一个 OpenOCD + telnet 4444 读内存**,不再每轮 spawn(旧 `rtt_read.py` 的 spawn
  方式在无线 CMSIS-DAP 上慢到会撑爆 1024 B 缓冲)。
- **必须每轮回写 RdOff(`mww`)**,否则目标端认为缓冲满,`NO_BLOCK_SKIP` 把后续日志全丢。
- 落盘时剥 ANSI 颜色码(`--raw` 可保留);收尾行 `dropped 0 B` 才是完整日志。
- 已知未测:真机跑通未验证(需探针+目标),telnet 口 4444 会与其他 OpenOCD 实例冲突。
- 文档:.Doc/RTT日志与调试通道.md §8。
- 自动启动:`tools/capture_rtt.bat` + `--loop` 常驻(下电收尾后回等待);单实例用占住本地
  4456 端口当互斥量。已实测:无探针时每 loop-delay 重试且不刷屏(60 s 节流),第二个实例被拒。
- 关闭:`tools/stop_capture.bat`(netstat 按 4456 取 PID → taskkill,再清 openocd.exe)。已实测。
  **坑**:`taskkill /F` 杀掉父进程时 finally 不执行,常驻 openocd 会变孤儿继续占探针,
  表现为之后烧录/抓取都报 `unable to find a matching CMSIS-DAP device`。
