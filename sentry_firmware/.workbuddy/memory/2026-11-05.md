## 小陀螺转速/功率核算(用户反馈"裁判系统功率不到 30W")

换算链(CHASSIS_ROTATE_SPEED=300deg/s,WHEEL_BASE=TRACK_WIDTH=300mm,RADIUS_WHEEL=60mm,速比19):
- 力臂(对角)= √(150²+150²) = 212.1mm;代码用 (150+150)×0.7071 折算,等价正确
- 轮子切向线速度 = 5.236rad/s × 0.2121m = 1.111 m/s
- 轮子输出轴 = 176.8 RPM;电机转子 = 176.8×19 = 3359 RPM(占 6000 RPM 限幅 56%,占空载 8300 的 40%)
- 单轮空载 3359 RPM 约 6~8W,四轮 24~32W

结论:裁判系统 30W 落在预期区间,**说明转速是达标的,不是故障**。要确证看转速而非功率(数圈 1.2s/圈,或 IMU Gyro[Z]≈5.24rad/s)。
轮径/RADIUS_WHEEL 是最敏感参数:若实际为 4 寸(101mm)则实际 356deg/s,6 寸(152mm)则 237deg/s,功率随之变化。

附带发现:referee_protocol.h 的 ext_power_heat_data_t 把 0x0202 的 float power 字段命名成 `reserved3` 且未解析 → 下位机目前拿不到底盘功率,将来做功率控制/UI 要按 float 解析该 4 字节。
power_control / super_cap 在 chassis.c 里仍是 #if 0 未接入,因此不存在因功率限制降速。

## 跃鹿 basic_framework 上游小陀螺值(核对来源:gitee hnuyuelurm/basic_framework master)

- `chassis.c` CHASSIS_ROTATE 分支:**`chassis_cmd_recv.wz = 4000;`**(硬编码魔数,注释"当前wz维持定值,后续增加不规则变速策略")
- 上游 MecanumCalculate **没有** √2 投影、**没有** wheel_ratio 换算:`vt = ±vx ± vy ± wz*L_CENTER` 直接喂速度环(转子 deg/s 域)。所以 4000 的量纲不是 deg/s,是"能转起来"的经验值。
- 上游底盘参数:WHEEL_BASE 350 / TRACK_WIDTH 300 / RADIUS_WHEEL 60 / 速比 19;速度环 Kp=4.5 Ki=0 MaxOut=15000。
- 按上游公式折算物理效果:L=(175²+150²)^0.5=230.5mm;vt=4000×5.6723=22689deg/s=3781RPM转子 → 输出轴199RPM → 轮速1.250m/s → **底盘实际≈311deg/s**。
- 对照本车 300deg/s / 3359RPM:**基本同一档位(低约4%)**,本车的 300 就是对齐跃鹿实际效果的等价取值。
- ⚠️ 关键坑:本工程补了 √2 与 wheel_ratio,若把 4000 直接抄进本工程,vt=4000×5.236×0.7071×18.14≈268000deg/s,会被 6000RPM 限幅直接打满。**数字不可跨工程照抄**。
