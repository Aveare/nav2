# 工程上下文与设计依据

## 1. 适用范围

用于接手现有工程、建立设计基线及处理文档与实现冲突。工程路径由当前任务确定，不绑定作者个人电脑目录。工程记录保存在目标工程；skill 文档描述通用工作方式，不承担实际项目的状态台账。

## 2. 事实分类

| 类别 | 能说明的事实 | 记录要求 |
| --- | --- | --- |
| 用户确认 | 需求、设计选择、已确认安装配置 | 记录确认内容与日期；与物理验证分开 |
| 源码现状 | 当前绑定、算法、宏与接口实现 | 附相对路径、符号及版本；不据此推断接线 |
| 实测 | 指定固件与条件下的设备或功能表现 | 附方法、条件、数据与固件身份 |
| 方案建议 | 尚未落实的候选结构或参数 | 明确选择理由和需要确认的条件 |
| 待确认 | 缺少证据或存在冲突的配置 | 指出影响范围与下一项确认动作 |

这些类别描述依据，并非单一优先级。源码决定实际软件行为，安装与测量决定物理事实，用户决定需求；不一致时保留差异并核实。

## 3. 冲突处理

1. 确认资料针对的工程、提交、板卡及固件是否一致。
2. 对照实际声明、实现、调用者、构建宏和任务入口，确认软件有效路径。
3. 对照接线、设备设置与测试证据，确认硬件实际状态。
4. 将差异、影响及解决依据写入主记录；仍缺依据时保留待确认状态。

用户最新报告仍能复现的故障，应保留或重开原问题。历史成功记录仅代表当时测试条件，不覆盖新证据。

## 4. 基线边界

通用代码来源见 [来源声明](provenance.md)。作者本地底盘开发经历见 [历史案例](jit-case.md)，仅用于故障定位参考。维护现有工程时，先确认其派生版本；不能假设已包含随包固定提交的全部接口或更改。
