# 基线审计：识别 AI 过度改动

## 1. 目的与立场

AI 辅助开发的主要风险不是"写不出"，而是**借参数适配之名重写结构**：新增包装层、重排函数、改动调用链、另建平行实现，导致工程偏离跃鹿模板且不可追溯。基线审计回答一个问题：**当前工程相对跃鹿基线到底被改了什么，哪些属于预期适配，哪些是结构性偏离。**

审计是只读操作：比对、分类、记录，不修改工程；属于允许的静态检查，不构成编译/烧录授权。处置（回退/收敛/保留）必须经用户确认后另行执行。

## 2. 何时执行

| 时机 | 用途 |
| --- | --- |
| 接手工程 | 建立"哪些文件被改过"的底账，再谈任务 |
| 新功能开工前 | 确认受影响文件的当前状态与原版差异，避免在他人改动上继续堆叠 |
| 故障排查时 | 优先怀疑最近改动：先审计，再谈参数与硬件 |
| 交付/中断前 | 将审计结果与验证状态一并记入工程主记录 |

## 3. 执行方法

### 3.1 文件级（工具）

```powershell
# 用户终端：PowerShell 版
powershell -ExecutionPolicy Bypass -File <skill根>/scripts/audit_baseline.ps1 -ProjectRoot <工程根> [-IgnoreEol]

# AI 沙箱/无 PowerShell 环境等价命令（脚本目录的上一级即 skill 根，两版逻辑一致）
python <skill根>/scripts/audit_baseline.py --project <工程根> [--ignore-eol] [--json]
```

脚本只读比对当前工程与 `assets/yuelu-basic-framework.manifest.json`（固定提交的逐文件 SHA-256），输出：

- **Unchanged**：与基线逐字节一致；
- **Changed**：内容有差异（对第一方 `.c/.h` 附带新旧符号差集：新增/消失的函数、`#define`、typedef，用于识别结构性改动；启发式提取，可能误报，需人工复核）；
- **Missing**：基线有而工程缺失（警惕：模块存在≠启用，删除需依据）；
- **Added**：工程有而基线没有（团队新增或 AI 新建文件，需按授权逐项分类）。

`-IgnoreEol` 将 CRLF/LF 归一后再哈希，用于排除换行符干扰；二进制文件不参与归一。

### 3.2 符号级（人工/半自动）

对 Changed 的第一方文件，用 `git diff --no-index` 逐行看差异，并核对：

1. **调用链**：`MotorControlTask()`、`RobotTask()`、`OSTaskInit()` 内的调用集合是否与基线一致；
2. **实例与配置**：`dji_motor_init`/`motor_init_config_t` 的结构是否保持，仅数值/ID/方向/反馈源变化；
3. **消息合同**：`robot_def.h` 的 Cmd/Upload 结构体字段与话题名是否原样；
4. **任务与文件集合**：任务数量、`.c/.h` 文件集合、构建文件清单是否原样。

### 3.3 派生版本注意

快照对应 [来源声明](provenance.md) 的固定提交。工程派生自其他提交或含团队先行改动时，首次审计会出现"基线噪音"：先把已知团队改动记入主记录，后续审计只看增量。

## 4. 分类判定

| 类别 | 典型内容 | 处置 |
| --- | --- | --- |
| 预期参数适配 | `robot_def.h` 数值、Init 配置中的 PID/ID/方向/反馈源、零位/限位、注释增补 | 正常；确认值来源后记录 |
| 预期功能补齐 | 原函数/预留分支内实现用户明确授权的新功能（如 TODO 处补功率限制） | 正常；记录依据与验证 |
| **结构性偏离（红旗）** | 新增/删除 `.c/.h`、新函数或函数签名变化、调用链增删、任务增删、消息字段/话题变化、重命名、直接寄存器或绕过模块直调 HAL、平行实现/包装层 | **暂停叠加改动**，与用户确认范围后回退或最小化 |
| 待分类 | Added 文件（团队工具、记录、测试脚本等） | 逐项问用户；不默认视为违规 |

回退方式：从快照复制原文件覆盖前，**必须**先保存当前版本内容到主记录或备份，并把已确认有效的参数（PID、ID、零位）重新移植回原结构——回退不是丢弃成果，而是把成果装回模板骨架。

## 5. 记录

按 [工程记录规范](development-handoff.md) 在主记录追加 DEV 条目：审计命令与参数、Unchanged/Changed/Added/Missing 计数、红旗清单与逐项处置、派生版本说明。只读审计本身不新建问题编号；由审计发现的缺陷按原编号或新编号进入问题台账。
