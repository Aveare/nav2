# 历史底盘故障接手案例

## 1. 案例用途

本案例说明配置与验证证据的边界，适用于接手横移异常或类似底盘故障。信息来自历史开发记录，非完整实验报告，不提供新车默认配置。

## 2. 已知条件与缺口

| 项目 | 历史信息 | 证据边界 |
| --- | --- | --- |
| 平台 | basic_framework，参考过 Mas/JIT；4 个 M3508、DJI 遥控器、CAN1 | 不能据此确定当前工程版本或接线 |
| 坐标/单位 | 前进 vx、向右 vy、逆时针 wz；本地参数 mm/s、degree/s | 属于当时派生实现，非通用协议 |
| 轮号 | 左前/右前/左后/右后曾出现 2/4/1/3 与 4/1/2/3 两组记录 | 未形成逐轮物理核验结论 |
| 使能 | 曾讨论回中自动使能与开关手动解锁 | 两种方案不得合并成既定实现。**现状（2026-10-27）：已按工程 DEC-005 采用"右上+左中+全回中"解锁并写入主机测试；回中自动使能随 DEC-001 否决，工程文档若仍描述该方案，以 DEC 台账为准** |
| 故障 | 横移有电机输出，但实际底盘横移异常 | 缺少最终改动后的目标/反馈/输出及固件身份 |

未有充分证据关闭该实体故障。PID、旋转速度、限幅与 ID 均不作为新工程默认值。

## 3. 接手与验收

先核对当前源码、板上固件和问题记录；逐轮确认机械位置、设备编号、方向、反馈新鲜度和轮型/布局。检查纯前进/横移/旋转目标及单位换算，再比较空载与落地反馈/输出，检验映射、几何、坐标、机械接触或饱和等假设。

沿用原问题编号，记录包括无效尝试在内的结果。关闭条件必须包含已确认配置下的实际横移验收；主机测试或编译通过只计入对应验证层次。
