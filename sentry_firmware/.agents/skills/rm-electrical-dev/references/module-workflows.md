# 模块实施与验收规范

## 1. 集成方法

读取本次涉及的模块章节。建立“输入 → 仲裁/状态 → 目标解算 → 反馈 → 控制输出 → 机构动作”的实际调用链，标注接口、任务及单位；配置确认按 [设计输入](design-intake.md)，架构与 API 按 [跃鹿规范](yuelu-framework.md)。

验收条件应与目标一致：数学解算可先验证纯轴输入和边界；驱动集成需验证实际资源、反馈与输出；机构行为需相应台架或整车证据。以下各项按改动范围采用，不要求局部修复重复整车调试。

以下行为和验收项按本次任务使用，不是要求每次调参都补齐一套保护框架。已有工程先核对原机制、记录缺口；用户只要求模板参数适配时，不因本表列有状态/超时/恢复就新增锁、看门狗、诊断字段、消息接口或任务。必要实现优先填原函数的预留分支，遵循[模板内适配原则](coding-contract.md#2-模板内适配优先)。

## 2. 底盘

**设计输入**：轮型/布局、轮序、轮径/轮距/轴距、传动比、正方向、反馈轴与单位、控制坐标、运行模式及限幅来源。

**集成路径**：核对 `cmd_task()` → 命令话题或板间通信 → `chassis_task()` → 运动学 → 电机参考接口 → 周期 `MotorControlTask()`。以上名称为基线导航，派生工程以实际符号为准。

**实施要求**：

- 运动学对应真实构型；全向轮、麦克纳姆轮、舵轮、差速和平衡底盘分别处理。
- 明确底盘/云台坐标转换、跟随及旋转模式的切换。换算逐段标注命令量纲、传动比和最终电机参考量纲。
- 轮速饱和处理评估合成运动比例；停止和恢复符合当前机构与仲裁设计。
- 舵轮补充角度反馈/回零、等价角与轮速翻转、转角范围及故障轮处理；平衡/轮腿补充状态估计、控制周期与跌倒处理。

**验收证据**：纯前进/横移/旋转目标；每个逻辑轮与物理轮、反馈编号和方向对应；反馈更新与输出限制；受影响模式及组合运动。空载轮转动仅证明该条件下输出，不证明落地运动正确。

## 3. 云台

**设计输入**：轴拓扑、各轴型号/传动、零位/限位、反馈来源和对应轴、IMU 安装、跨圈与线缆约束。双 yaw 必须区分串联、同轴多驱及独立云台。

**实施要求**：

- APP 管理模式与目标，Motor Module 执行已配置的闭环和反馈选择。调用反馈切换接口前核对实现及指针生命周期。
- 编码器、IMU 与视觉量明确坐标和单位；模式/反馈切换处理目标连续性、积分和限位。
- 视觉协议确定角度/角速度/目标点/姿态等数据含义、时间戳、有效期和失联行为，并明确上下位机职责。

**验收证据**：各轴方向与反馈、零位/跨圈、限位、目标跟踪、模式切换及数据过期。多轴构型需验证轴间分配与坐标变换，重力轴还需验证保持或制动行为。

## 4. 发射与供弹

**设计输入**：摩擦轮/供弹/拨盘/盖板结构，型号/方向，步距，反馈，允许发射条件，热量/频率/弹速依据。

**实施要求**：

- 在本次发射功能开发范围内说明原状态机的待机、准备、就绪、发射、故障和恢复行为；优先复用现有状态，不要求参数适配任务重建这些状态。
- 发射互锁检查模式、到速、反馈、机构就绪和适用规则条件；缺少有效数据时行为须显式定义。
- 单发、连发、退弹和堵转恢复定义重试上限；重复命令或断链不得隐式补发历史动作。

**验收证据**：就绪前禁止动作、单次/连续命令语义、堵转/恢复、过期命令及规则数据缺失分支。机械步距和到速阈值必须有配置依据。

## 5. 专用机构与自主协同

机械臂、升降、夹爪等按关节/执行器建立实例，明确原点、限位、负载、工作空间、互锁及动作序列退出路径。验收覆盖回零、限位、流程中断和恢复；重力负载按设计验证保持/制动。

导航、雷达、飞控等明确计算职责、坐标/时间基准、命令有效期、仲裁与接管。STM32 仅承担已约定控制与通信功能。按 [兵种要求](robot-types.md) 补充任务相关设计，验收数据无效、失联及接管后的实际行为。

## 6. 通信、任务与资源

建立资源所有者表：CAN 组帧、UART/DMA、定时器/PWM、ISR/任务、共享缓冲。多板通信明确双方类型/版本、控制权限和命令生效条件。

CAN 检查反馈 ID、控制组帧、注册/过滤、回调、错误状态、帧频率及发送拥堵。DMA/回调核对长度、生命周期、并发和重入。调度需验证初始化前提、实际周期及耗时；通信异常应先定位链路证据，再判断控制参数。

验收包含协议长度/字节序/CRC、异常包、断链、重连和资源冲突相关分支。单槽消息中心适合最新状态；不可据此保证事件不丢或跨任务线程安全。

## 7. 故障与恢复

按受影响设备建立“触发 → 检测 → 状态转换 → 输出动作 → 恢复条件”表，覆盖未初始化、无首次有效反馈、命令过期、失联、异常数值、限位/堵转及急停等相关场景。

与风险和负载相适应地定义可测条件：检测/超时时间、故障锁存与复位方式、故障期间命令优先级、恢复滞回及接管条件。验收应检查实际时序和输出，而非仅检查状态名称。

零输出、零速度、保持位置、制动、有序回撤是不同动作，按机械设计选择。恢复条件不得隐含为收到任意一帧立即恢复全部机构。

重力机构的制动、自锁或失电状态未知时，记录保护动作待确认及影响范围；可继续链路诊断和状态设计，候选动作不得直接进入实际使能或机构验收。

定位故障记录模式/使能原因、目标/反馈、更新时间、输出饱和、总线状态及物理动作。每次调整应检验明确假设，并记录无效尝试。问题关闭按 [接手规范](development-handoff.md) 保留实际版本与验证证据。
