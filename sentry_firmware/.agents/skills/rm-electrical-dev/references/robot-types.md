# 兵种与机械构型设计要求

本文提供依据官方资料入口及战队一手案例归纳的工程设计检查项。兵种身份、机械构型和任务范围分别确认；具体限值及参赛权限以适用赛事文件为准，表格不指定固定 BOM。配置确认按 [设计输入规范](design-intake.md) 执行。

## 1. 兵种设计要求

| 兵种 | 电控重点 | 必要设计确认 |
| --- | --- | --- |
| 常规步兵 | 底盘、云台、发射联动，遥控/视觉仲裁、裁判数据约束 | 轮型/轮序/坐标、yaw/pitch 拓扑、是否滑环、发射机构和弹种、单/多板、视觉合同 |
| 英雄 | 供弹/发射与重载云台、底盘协同，机构和状态更多 | 实际弹种/供弹机制、各轴负载/传动、堵转处理、云台与底盘职责、功率与热量来源 |
| 工程 | 机械臂/夹爪/升降等多执行器、原点/限位、动作序列和互锁 | 关节拓扑、驱动/反馈/负载、气泵/阀/IO、工作空间、防碰撞、控制器接口、急停/保持/恢复 |
| 哨兵 | 定位/导航/决策与自瞄/火控、失联处置、上下位机协同 | 自主功能范围、定位源和导航合同、双 yaw/多云台具体拓扑、IMU 归属、人工接管与降级 |
| 空中 | 飞控稳定与云台/发射协同，遥控/图传/电量和失控处置 | 飞控与 STM32 的责任边界、链路与权限、模式切换、稳像坐标、电源/低电量/失控流程 |
| 飞镖 | 上膛/发射/复位流程、位置反馈、触发与重复命令防护 | 镖架/储能/执行器、原点/限位、裁判事件/触发合同、瞄准与制导归属、上膛/发射互锁 |
| 雷达 | 识别/定位/融合、标定/坐标和时间同步、赛事通信 | 摄像头/雷达数量与处理设备、标定/地图、报文/坐标有效期、通信渠道、是否实际需要 MCU/电机 |

## 2. 构型附加要求

构型要求与兵种要求叠加使用，例如英雄舵轮或哨兵多 yaw。

| 构型 | 电控重点 | 必要设计确认 |
| --- | --- | --- |
| 平衡/轮腿步兵 | 常规功能之外增加姿态/腿部/平衡闭环与状态估计 | 自由度和几何、IMU 坐标、反馈/估计、控制频率和算力、跌倒/支撑/模式切换 |
| 舵轮底盘 | 每模块转向与轮驱协调、等价角处理、回零和故障轮策略 | 每轮驱动/转向型号与 ID、角度反馈/范围/零位、几何、翻转策略、掉线/堵转降级 |
| 多 yaw/多云台 | 轴间反馈、运动分配和坐标变换 | 串联/同轴多驱/独立云台、各轴职责与反馈、绝对/相对角、控制优先级、线缆/限位 |

设备存在、数量和处理端均需按实际设计确认。工程兵种可以采用不同自由度机构，哨兵定位可以采用不同传感器；雷达识别和融合的计算职责应在系统分工中单独定义。

## 3. 规则与协议依据

先确认比赛类型、年份和组别，再到 [RoboMaster 官方资料中心](https://bbs.robomaster.com/wiki/20204847) 查适用文件。至少区分规则手册、机器人制作规范、参赛手册、裁判系统手册/串口协议和后续补充公告。

资料索引核查日期： 2026-10-10；[RMUC 规则目录](https://bbs.robomaster.com/wiki/20204847/809871) 列有 2026 规则 V2.2.0（2026-08-07）。这是**索引元信息**，本文未逐条提取其完整正文，不提供由此推定的功率、弹速、热量、尺寸或自主权限数值。实施时仍须打开对应文件，记录版本/条款/日期；文件版本变动需复核，索引核查日期仅描述本次资料状态。

当前工程 `referee_protocol.h` 的字段、枚举和旧裁判代码也要和实际硬件/协议版本对齐；解析正常不能证明所取字段仍是当季约束值。未能访问正文时把合规项标待确认，继续不依赖该限值的工作。
