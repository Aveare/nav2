# 文档存放与管理规则

> 制定:2026-11-27(DEV-20261127-000119)。适用:人 + AI。
> **一句话:共用文档留在 `.Doc/spec|guide|plan|history|gate|data`;兵种专属文档一律进 `.Doc/robots/<robot>/`;
> 过期文档进 `.Doc/history/archive/`。目录即归属,归属即分支。**
> 本文件是 `.Doc/spec/兵种分支协作规范.md` 的文档侧细则;代码路径归属仍以那份为准。

## 1. 三层存放模型

| 层 | 目录 | 放什么 | 谁维护 | 分支资格 |
|---|---|---|---|---|
| **共用** | `AGENTS.md`、`README.md`、`RM_DEVLOG.md`、`.Doc/{spec,guide,plan,README.md}` | 跨兵种都成立的规范、方法、工具、流程、决策 | 全员 | 只在 `main`（或 `fix/shared-*`） |
| **兵种专属** | `.Doc/robots/<robot>/` | 只对某一个兵种成立的参数、设计、计划、操作说明 | 该兵种负责人 | 只在 `infantry`/`sentry`/`heavy` 分支 |
| **历史归档** | `.Doc/history/`、`.Doc/history/archive/<原目录>/` | 已结项计划、审查报告、被取代的设计、旧教程 | 维护者 | 只追加，不改写 |

当前有三个兵种库：`.Doc/robots/infantry/`、`.Doc/robots/sentry/`、`.Doc/robots/heavy/`。
每个库必须有 `README.md` 作索引，说明"这个兵种现在是什么状态、本目录有什么、入口在哪"。

## 2. 判定顺序（写新文档前问三遍）

1. **换个兵种还成立吗？** 成立 → 共用；只对某兵种成立 → `robots/<robot>/`。
2. **是规则还是结论？** 规则、方法、流程 → 共用 `spec|guide`；某兵种的数值与实测结论 → `robots/<robot>/`。
3. **还有效吗？** 已被取代/已结项 → `history/archive/`，不要留在活跃目录里"备查"。

判不准时**默认按兵种专属**存放（更严），并在 `robots/<robot>/README.md` 登记；确认共用后再上移。

## 3. 兵种库内部结构（固定）

```
.Doc/robots/<robot>/
├─ README.md        # 索引:当前状态、入口(代码/config/DEVLOG)、目录说明
├─ DEVLOG.md        # 本兵种台账:当前状态、问题、近期 DEV(标题带 [ROBOT] 标记)
├─ design/          # 设计说明:拓扑、控制结构、为什么这么做
├─ params/          # 本兵种参数证据表、调参结论、标定记录
├─ plans/           # 仍在执行或未来要做的计划(结项后移 archive)
└─ ops/             # 本兵种专属操作:烧录顺序、台架步骤、放行检查单
```

- `DEVLOG.md` 是**本兵种唯一台账**：状态、未关闭问题、近期 DEV 都写这里；根 `RM_DEVLOG.md`
  只留公共内容，不再登记兵种专属条目。两边标题/行都带类型标记（`[公共]/[INFANTRY]/[SENTRY]/[HEAVY]`）。
- 文件名用主题名（`底盘功率.md`、`云台三轴.md`），不加兵种前缀——目录已经表明兵种。
- 跨兵种对照（例如"步兵 vs 哨兵功率"）放共用 `spec/`，并按兵种分节；不要把对照表塞进某个兵种库。
- 兵种库**不放**：共用规范副本、其他兵种文档、历史审查报告。

## 4. 移动与改名规则

1. 用 `git mv`，保留历史；移动后必须同步所有引用（`check-links` 会抓 `.Doc/` 悬空）。
2. 移动即归属变更：把文档从共用移进兵种库，等于把它划给该兵种分支维护。
3. 兵种库之间**不互相引用文件路径**；需要引用时写"见 `robots/<robot>/` 目录"，不写具体文件。
4. 删除文档前先确认：`git log --diff-filter=D` 可追溯，且没有活跃文档引用；优先归档而不是删除。

## 5. 分支与评审

| 文档位置 | 允许在哪些分支改 | 合并方向 |
|---|---|---|
| 共用 `spec|guide|plan`、根三件、根 `RM_DEVLOG.md` | `main` / `fix/shared-*` | 直接进 `main`，再下行同步 |
| `.Doc/robots/<robot>/**`（含 `DEVLOG.md`） | 该兵种分支及其个人短分支 | 短分支 → 兵种分支；验证后兵种分支 → `main` |
| `history/**` | `main` | 只追加 |

**并行开发的核心收益**：步兵改 `robots/infantry/DEVLOG.md`、哨兵改 `robots/sentry/DEVLOG.md`，
不再争同一份 `RM_DEVLOG.md`；公共决策才动根台账。

机器守卫：`tools/check_robot_scope.py` 已把 `.Doc/robots/<robot>/` 识别为该兵种私有路径；
在 `sentry` 分支改 `robots/infantry/` 会直接 FAIL（`--gate` 单行结论）。

## 6. 文档分级联动

`.Doc/spec/文档阅读分级.md` 的 A/B/C/D 分层按本规则重算：

- A 层只放共用入口（AGENTS、阅读分级、兵种分支规范、README、DEVLOG §0）；
- B 层放共用规范与操作（spec/guide）；
- 兵种库文档按"做该兵种的事才读"归入 C，不作为全局必读；
- `history/` 归 D；E 层已清零，且**只减不增**（不再引入第三方快照、外部工具记忆、过期会话工件）。

## 7. 维护检查

```powershell
python tools/check_robot_scope.py --gate   # 兵种归属(含 .Doc/robots/**)
python tools/refactor_gate.py check-links  # .Doc 引用不悬空
git ls-files ".Doc/robots/*"               # 各兵种库文件清单
```

每赛季末复核一次：结项的 `plans/` 移 `history/archive/`；失效的设计移档；共享文档里出现某兵种专属数值时，拆回该兵种库。
