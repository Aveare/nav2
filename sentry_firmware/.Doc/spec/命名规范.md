# 命名规范

> 适用：本工程第一方代码（`apps/` `components/` `framework/` `ports/` `config/`）；测试桩同规则，层级标 `TESTS`。
> 不适用：`Drivers/` `Middlewares/`（STM32 HAL / FreeRTOS / CMSIS / SEGGER，第三方 ABI 不改）；`Src/` `Inc/` 仅 USER CODE 区可改。
> 机器闸门：`tools/check_naming.py` + `.clang-tidy` + `tools/check_macros.py` + `tools/check_macro_dups.py`。
> 制定：2026-11-23（工程统一化收官，DEV-20261123-01）。风格依据：Barr-C / MISRA-C 命名条款、Linux 内核风格、Google C++ Style（C 子集）。

## 0. 为什么需要一份独立规范

命名不是审美问题，是**检索成本**问题。同一个概念出现 `DJIMotorSetRef`、`dji_motor_set_ref`、`SetRef` 三种写法时，`grep` 就失效，排障只能靠记忆。规范的目标只有一个：**看到名字就能定位模块、猜到职责、搜到全部调用点**。

## 1. 五条铁律

| # | 规则 | 违反后果 |
|---|---|---|
| 1 | 文件名、函数名、变量名一律 `snake_case` | 跨平台大小写不敏感文件系统会撞名 |
| 2 | 函数名 = `模块前缀_动词[_宾语]` | 无前缀函数无法判断归属，改名时漏调用点 |
| 3 | 类型 `_t`、枚举 `_e`、宏全大写 | 读代码时无法区分类型/宏/变量 |
| 4 | 宏必须带域前缀，禁止单字母 | 宏是全局文本替换，裸名会污染所有包含者 |
| 5 | 平台/第三方 ABI 名不动，登记例外 | 改 `HAL_*`/FreeRTOS 钩子会直接链接失败 |

## 2. 目录与文件

- 目录全小写 `snake_case`；一层只表达一个概念。
- 模块目录内**不混放"通用文件 + 厂商子目录"**：要么全平铺（如 `components/motor/` 的 `dji_motor.c` / `dm_motor.c` / `ht_motor.c`），要么全部进子目录。
- 文件 `snake_case.c/.h`，一个模块一个目录；文件名与模块前缀一致。
- 配置：`config/<robot>_<year>/config.h` 为唯一伞头，子头 `config_<域>.h`；业务代码只 `#include "config.h"`。
- 装配：`apps/<robot>/app/` 放 `profile.h` / `robot.c` / `robot_def.h` / `robot_task.c`；骨架根层只留目录。

## 3. 类型

```c
typedef struct { ... } chassis_ctrl_cmd_t;   // 结构体/联合/typedef 统一 _t
typedef enum   { ... } gimbal_mode_e;        // 枚举统一 _e
```

- 全小写 `snake_case`，`_t` / `_e` 结尾；禁止 `_s`、`Instance`、PascalCase。
- 枚举常量 `UPPER_SNAKE_CASE`，带域前缀：`LOADER_STOP`、`ENEMY_COLOR_RED`、`ROBOT_STATUS_READY`。
- 匿名结构体成员不强行改名（`rc` / `mouse` 是协议字段名，登记例外）。

## 4. 函数 / API

**格式：`模块前缀_动词[_宾语]()`**，全小写。

| 动词 | 用途 | 例 |
|---|---|---|
| `init` / `deinit` | 初始化 / 反初始化 | `chassis_init()` |
| `task` | RTOS 任务体（唯一允许的名词例外） | `gimbal_task()` |
| `update` / `process` | 周期更新 / 处理 | `heat_guard_update()` |
| `set` / `get` | 写 / 读 | `dji_motor_set_ref()` |
| `calc` / `apply` | 纯计算 / 施加输出 | `chassis_mecanum_calculate()` |
| `is` / `has` | 谓词 | `can_comm_is_online()` |
| `send` / `recv` | 收发 | `referee_send()` |
| `parse` / `encode` / `decode` | 编解码 | `ax650_pose_pack()` |
| `register` / `reload` | 注册 / 喂狗 | `daemon_register()` |
| `enable` / `disable` / `stop` | 使能 / 失能 / 停止 | `dji_motor_enable()` |

- 模块名与文件名一致；子模块可用二级前缀：`cmd_authority_arbitrate()`、`heat_guard_init()`。
- 静态函数同样带模块前缀，不用 `s_` 前缀（`static` 已经表达可见性）。
- 中断/回调：`模块_irq_handler()` / `模块_rx_callback()`；HAL 回调保留 `HAL_*`。
- 禁止无前缀的 `Init()`、`Update()`、`SetRef()`。

## 5. 变量

- 局部变量 / 参数 / 结构体成员：`snake_case`，见名知意，禁止单字母（循环下标 `i/j/k` 除外）。
- 文件级静态 / 全局：`snake_case`；单例可用模块名（`ins_state`、`bmi088`）。
- 布尔量用 `is_` / `has_` / `enable` 语义；计数量用 `_count`，不用 `Cnt`/`Num` 混写。
- 单位写进名字或注释：`_ms` `_us` `_deg` `_mm` `_rpm` `_deg_s`；同一变量不得混域。

## 6. 宏与枚举

```c
#define CHASSIS_WHEEL_BASE 500      // 域前缀_语义,全大写
#define SHOOT_FRICTION_TARGET_RPM 4000.0f
#define MATH_ABS(x) (((x) > 0) ? (x) : -(x))   // 函数式宏参数必须带括号
```

- 全大写 `UPPER_SNAKE_CASE`，域前缀（`CHASSIS_`/`GIMBAL_`/`SHOOT_`/`REFEREE_`/`MATH_`/`FW_`…）。
- **禁止单字母宏**；禁止无前缀裸宏（`PI`/`TRUE`/`mat`/`DoFreq` 已清理）。
- 布尔用 `<stdbool.h>` 的 `true/false`，不再自定义 `TRUE/FALSE`。
- 函数式宏参数必须加括号；能写成 `static inline` 的优先写函数。
- 宏只在头文件定义；`.c` 内局部宏加模块前缀并 `#undef`（如无必要，改 `static const`）。

## 7. 缩写表（只允许这些）

`imu` `ins` `can` `uart` `usart` `dma` `adc` `pwm` `spi` `i2c` `dwt` `rtt` `kbm` `rc` `ref` `msg` `mem` `err` `diag` `tel` `calib` `daemon` `chassis` `gimbal` `shoot` `heat` `ax650` `dji` `dm` `ht` `ekf` `pid` `crc` `fw` `math` `ui` `vt`

不在表内的缩写一律写全（`count` 不写 `cnt`，`temperature` 不写 `temp` 除既有 API）。

## 8. 例外清单（ABI / 平台 / 第三方）

| 类别 | 例子 | 理由 |
|---|---|---|
| STM32 HAL / CMSIS | `HAL_GPIO_WritePin`、`__get_BASEPRI` | 厂商 ABI |
| FreeRTOS / CMSIS-RTOS | `vApplicationStackOverflowHook`、`pcTaskGetName`、`osDelay` | 内核要求固定名 |
| CubeMX 生成 | `MX_CAN_Init`、`CS1_ACCEL_Pin`、`ADDR_FLASH_SECTOR_*` | 生成器命名，改了就丢 |
| 配置选择 | `ONE_BOARD` / `CHASSIS_BOARD` / `GIMBAL_BOARD` | 板型选择，跨文档契约 |
| 断言出口 | `fw_assert_fail` | `configASSERT` 固定符号 |
| 协议字段 | `rc` / `mouse` / `Cilent_ID`（原文拼写） | 线上布局/对端固件契约 |

例外必须登记在 `tools/check_naming.py` 白名单或 `.Doc/gate/*-allow.txt`；新增例外要写理由。

## 9. 机器闸门

```powershell
python tools/check_naming.py          # 文件/函数/类型/宏/变量命名
python tools/check_macros.py          # 宏账本 + config 子头跨文件 #if
python tools/check_macro_dups.py      # 同名不同值 / 未登记重复 / 单字母宏
python tools/check_source_lists.py    # Makefile 与磁盘 .c 一致
python tools/check_symbol_contract.py # 工具脚本引用的符号仍存在
```

`clang-tidy` 配置在 `.clang-tidy`，规则与本文一致；本机未安装时以 `check_naming.py` 为准。

## 10. 判据

- 新增/改名后 `check_naming.py` 必须 PASS，违例数只减不增。
- `grep -rn "模块名"` 能找全一个 API 的所有调用点。
- 新人只看名字能判断：属于哪个模块、是读还是写、单位是什么。
- 任何例外都能在本文 §8 或 allow 清单里找到理由。
