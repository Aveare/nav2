# 多兵种切换架构

> 制定:2026-11-23(DEV-20261123-02)。参考了 `C:/RoboMaster/RM_shaobin` 的**架构形态**——
> 仅目录/装配/开关组织方式,**未取用其中任何参数、标定值、PID 数值或代码**。

## 1. 哨兵参考工程的形态(反面教材为主)

| 方面 | RM_shaobin 做法 | 问题 |
|---|---|---|
| 工程 | 整仓复制步兵工程改名哨兵 | 双仓漂移:步兵的修复不会带过来 |
| 切换 | `CHASSIS_TUNING_ONLY` + `SENTRY_*_ENABLE` 宏嵌在 `robot.c/robot_task.c/gimbal.c` 里 | 共享代码布满兵种 `#if`,infantry 路径被哨兵代码污染 |
| 配置 | config 仍叫 `robot_infantry_2026.h` | 名实不符;参数与兵种无绑定 |
| 兵种模块 | `sentry_control.c/sentry_yaw.c` 直接塞进 `application/gimbal/` | 兵种代码与共享代码混目录 |
| 构建 | CMake GLOB 全 application,宏裁剪 | 无法按兵种裁剪编译单元,骨架兵种也编译全量 |

结论:这套形态只适合"临时单兵种调车",不适合多兵种共存。

## 2. 本工程方案(已实现)

### 2.1 结构

```
apps/
├─ common/app/                    # 通用装配壳:不认识任何兵种
│  ├─ app_profile.h               # app_profile_t 契约(init/run_200hz/ins_init/标志)
│  ├─ app_shell.c                 # 板级初始化/任务创建/喂狗/err 消费/兵种钩子调度
│  ├─ robot.h / robot_def.h / robot_task.h
├─ infantry/app/
│  ├─ profile.h                   # include config.h + 声明步兵标识
│  ├─ assembly.c                  # g_app_profile:接线 cmd/gimbal/shoot/chassis + AX650 钩子
│  └─ cmd/ chassis/ gimbal/ shoot/
├─ heavy/app/                     # profile.h + assembly.c(服务骨架,init/run 为空是显式的)
└─ sentry/app/                    # 同上;哨兵专用模块将来放 apps/sentry/<module>/
```

- **共享代码零兵种 `#if`**:兵种差异只出现在 `apps/<robot>/` 内。
- **配置按兵种分目录**:`config/<robot>_<year>/config.h`;CMake 用 `ROBOT_PROFILE` +
  `CONFIG_PROFILE` 选择,业务代码只 include `"config.h"`。
- **切换动作 = 换一个 CMake 变量**:`cmake -B build_<robot> -DROBOT_PROFILE=<robot>`。

### 2.2 兵种接入最小步骤

1. `apps/<robot>/app/profile.h`:include 本车 config,定义 `PROFILE_ROBOT_<X>`。
2. `apps/<robot>/app/assembly.c`:定义 `g_app_profile`(init/run_200hz/ins_init/calib_enable/ui_enable)。
3. `config/<robot>_<year>/config.h`:本车参数唯一来源。
4. 兵种专用模块放 `apps/<robot>/<module>/`,不进 `components/`。
5. CMake 自动 GLOB `apps/<robot>/*.c`;Makefile 是步兵单兵种清单,不登记非步兵源。

### 2.3 与 RM_shaobin 的适配点映射

| RM_shaobin 概念 | 本工程落点 | 说明 |
|---|---|---|
| `CHASSIS_TUNING_ONLY` 总开关 | `assembly.c` 的 init/run 挂空 + profile 编译裁剪 | 不再污染共享代码 |
| `SENTRY_*_ENABLE` 特性开关 | `apps/sentry/app/assembly.c` 决定接线;特性宏进本兵种 config | 开关只裁剪本兵种编译单元 |
| `sentry_control.c` 串级 PID | `apps/sentry/gimbal/gimbal.c`:大 yaw/pitch 达妙 MIT 力矩环,小 yaw GM6020 相对角/速度环 | 参数进 sentry config |
| `sentry_yaw.c` 雷达朝向 | `apps/sentry/gimbal/gimbal_alloc.h`:世界目标 → 大/小 yaw 分配纯函数 | 可主机单测 |
| 大 yaw 达妙/小 yaw GM6020 接线 | `dm/dm_motor.c`、`dji/dji_motor.c` 通用组件;实例注册在 `gimbal_init` | 参数不预置,按实车重标 |

## 4. 机器守卫

- `check_macro_dups.py --profile <p>`:config 只扫当前兵种目录;跨 profile 同名宏不是冲突。
- `check_source_lists.py`:Makefile 只对 infantry 负责,跳过 `apps/heavy/`、`apps/sentry/`。
- `tests/run_profile_tests.ps1`:编译每兵种 `profile.h` + `assembly.c`(host)。
- 反向依赖已消除,新增组件不得 include `apps/` 头(AGENTS 既有红线)。
