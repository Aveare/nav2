# 架构与开发指南

> 2026-11-22 B12 更新:本文件描述**当前**自研框架(B0a~B12 已收口)。升级前(跃鹿 APP→Module→BSP→HAL)的历史说明见 §1.5 与 `git log`;逐文件定位见 skill 的 `references/code-map.md` v2。

## 1. 分层

```
┌──────────────────────────────────────────────────────────────┐
│ apps/           装配层(按兵种)                                │
│   <robot>/app/  profile.h + robot.c + robot_def.h + robot_task.c │
│   cmd/ chassis/ gimbal/ shoot/ (infantry 实装)               │
├──────────────────────────────────────────────────────────────┤
│ components/     组件:设备协议 + 控制器 + 组件算法             │
│   motor(平铺 dji/dm/ht/servo) control crc math imu remote     │
│   referee ax650 calib super_cap can_comm(休眠) daemon alarm   │
├──────────────────────────────────────────────────────────────┤
│ framework/      平台无关框架(零 RTOS/HAL include)             │
│   kernel err mem msg diag(含 telemetry) types general_def    │
├──────────────────────────────────────────────────────────────┤
│ ports/          平台落地                                      │
│   stm32f4/*_port(HAL 外设)  freertos/kernel 后端             │
├──────────────────────────────────────────────────────────────┤
│ HAL  Drivers/ + Src/Inc/(CubeMX 生成)                        │
└──────────────────────────────────────────────────────────────┘
```

分层纪律(违者审计红旗):

1. **依赖方向**:`apps → components → framework → ports → HAL`,绝不反向;components/ports/framework 不得 include `apps/` 头。
2. **framework 零平台 include**:不得出现 FreeRTOS.h/task.h/cmsis_os.h 或 HAL 头;需要 RTOS 的能力一律经 `ports/freertos` 后端。
3. **逻辑层禁触硬件句柄**:apps/components/framework 内不得出现 `hcan*/husart*/htim*` 等;Init 时注入 `&hcan*/&huart*` 属合规(依赖注入),Task/控制函数中直接访问 = 禁止。
4. **单写者**:每个消息话题/共享结构体只有一个生产任务。
5. **错误上报不挂死**:运行期错误走 `err_report` + 安全态(LOGERROR/停机);启动期配置错误才 fail-fast(`.Doc/gate/redflags` 已裁决清单)。
6. **`#if` 只在 profile.h/config**:装配开关统一入口,禁止散落业务代码。

## 2. 启动与任务

启动链:`Src/main.c: main()` → `MX_*_Init` → `apps/infantry/app/robot.c: robot_init()`【关中断:BoardInit(DWT+LOG)→各应用 Init→OSTaskInit】→【开中断】→ `MX_FREERTOS_Init()` → `osKernelStart()`。

`robot_init` 同时:读 `RCC->CSR` 复位原因(读后 RMVF 清零)、注册必活心跳、运行期错误消费。

| 任务 | 频率 | 循环体 | 栈(word) |
| --- | --- | --- | --- |
| INS | 1kHz | BMI088 读取 + 四元数 EKF 解算 + 视觉发送 | 1024 |
| MOTOR | 1kHz | 三环 PID + CAN 组帧发送 | 256 |
| DAEMON | 100Hz | DaemonTask + 蜂鸣器 + `diag_watch_tick` | 128 |
| ROBOT | 200Hz | cmd_task + Gimbal/Shoot/Chassis | 1024 |
| UI | 可选(TASK_UI_ENABLE) | 裁判系统 UI 绘制 | 512 |

任务创建一律 `kernel_task_create`(framework/kernel),启停由 `TASK_*_ENABLE` 宏或 profile 决定;禁止注释启停、禁止直接调 `osThreadCreate`。四个必活任务每拍 `diag_watch_kick`,全活才喂 IWDG。

## 3. 数据流

**控制流(cmd_task 200Hz)**
```
遥控器(USART3 回调→rc_ctrl) / 自瞄(0x0503) / 键鼠 → cmd_task
  ├─ CalcOffsetAngle()          yaw 单圈角-零位=offset(±180 折返)
  ├─ 仲裁(AuthorityArbitrate)  失联>急停>拨轮/锁存>运行
  └─ msg_publish → [chassis_cmd] [gimbal_cmd] [shoot_cmd]
        ↓ msg_recv(深度 1)            ↓                    ↓
   chassis_task(斜坡/跟随/麦轮)  gimbal_task(双前馈/调度)  shoot_task(互锁/热量)
```

**反馈流(中断)**:`ports/stm32f4/can_port.c` 的 HAL RX 回调 → 遍历实例匹配 hcan+rx_id → `memcpy` → 组件回调(`dji_motor_decode`:解析/滤波/多圈/`daemon_reload`)。

**发送流**:`CANTransmit()` → 每总线发送 FIFO(BASEPRI,满丢最老+计数)→ 入邮箱 → TX 空中断续传,非阻塞。

**消息语义**:发布/订阅按名字注册;每个订阅者深度 1(只保最新);同一话题 `data_len` 必须一致;`msg_publish` 禁止 ISR 调用(直接丢弃并计数)。话题清单与 12 项语义对照见 `.Doc/history/archive/gate/msg-semantic-map.md`(历史归档)。

**串口归属**:USART1(PA9/PB7)在同一时刻只能有一个所有者,由
`AX650_UART1_ENABLE` 与 `CHASSIS_VOFA_UART1_ENABLE` 编译期二选一:前者为
921600 8E1 自瞄私有帧,后者为 921600 8N1 系统/底盘 VOFA JustFloat 调试。
USART6 由 `YAW_AUTO_VOFA_USART6_ENABLE` 二选一:0=裁判系统 115200 8N1
(热量、冷却、弹速、功率和 UI),1=自瞄 yaw VOFA 调试(115200 8N1,暂停裁判 UI/数据)。
USART3 固定为 DBUS 遥控;两条调试链的内容按口分离。

## 4. 如何加一个新组件(以"新增某传感器"为例)

1. 在 `components/<name>/` 建 `<name>.c/.h`,遵循实例模式:
   - `<Name>_Init_Config_s` + `<Name>Instance` + `<Name>Init()`(向对应 port 注册回调,返回实例指针);
   - 实例内放 `DaemonInstance*` 做离线检测;头文件写清单位/坐标/方向/生命周期;
2. `framework/` 里只放纯逻辑;平台相关部分放 `ports/stm32f4/<x>_port.*`;
3. CMake 自动 GLOB;**Makefile 需手动登记源文件**(`tools/check_source_lists.py` 会查);
4. 在 apps 的对应 Init 里调用 `<Name>Init(&conf)`,保存实例指针;
5. 组件内不 sleep、不挂死;运行期错误 `err_report` + 安全态。

## 5. 如何调一个新应用 / 新骨架

1. 在 `apps/<profile>/` 下加 `<name>.c/.h`,实现 `<Name>Init()`(注册设备)与 `<Name>Task()`(周期控制);
2. `robot.c` 的 `robot_init/RobotTask` 接线;`robot_task.c` 用 `kernel_task_create` 创建任务;
3. 需要 cmd 下发控制:在 `robot_def.h` 加控制/反馈结构体(**pack(1) 布局守卫与对端同步**),cmd 注册发布、app 订阅;
4. 参数一律放 `config/infantry_2026/config.h`(语义名+一行依据),不散在业务代码;
5. 新兵种骨架:复制 `profile.h` 锚点 + 目录,CMake `-DROBOT_PROFILE=<name>`;heavy/sentry 当前仅锚点。

## 6. 构建体系

- **CMake**(GLOB 自动收集,`ROBOT_PROFILE` 选骨架)与 **Makefile**(显式源列表,步兵)双体系;每次新增/移动 .c 后两者都要同步(CMake 重跑 configure)。
- `-Werror`:任何 warning 都是错误;**Makefile 与 CMake 的 text 差异仅允许工具链/优化选项造成**。
- CubeMX 重新生成只覆盖 Src/Inc 生成区,`USER CODE BEGIN/END` 之间保留。
- 烧录:`tasks.json` 的 `download_dap`/`download_jlink`;日志:RTT(`JlinkRTTClient`)。
- 升级期闸门:`tools/refactor_gate.py check`(G1~G5)+ `check_source_lists.py`(G10)+ `check_sections.py`(G5c)。
