# 哨兵 Sentry 工程团队协作指南（Git / GitHub）

> 远程仓库：https://github.com/youyucat/RM-JIT-CR （私有，默认分支 `main`）
> **项目身份**:本仓库当前交付目标是哨兵 Sentry。有效应用为 `apps/sentry/`,有效参数为 `config/sentry_2026/`;infantry/heavy 仅用于共享回归、历史追溯和兼容。
> 本指南覆盖日常 90% 的操作；疑难情况问仓库管理员，不要凭感觉 force push。
> AI 协作契约见根目录《AGENTS.md》，代码纪律见《.Doc/spec/必须做&禁止做.md》。
>
> **分支模型(2026-11-26 起)**：`main` = 共享主干；`infantry` / `sentry` / `heavy` = 长驻兵种分支。
> 兵种核对、路径归属、提交与提醒规则以 **《.Doc/spec/兵种分支协作规范.md》** 为准（每对话开工前读一次）；
> 本指南只保留日常命令与 FAQ，两者冲突时以规范为准。

## 0. 一页速查

```powershell
# ── 每次 STM32 工程改动开工(当前分支 = 本兵种分支) ──────────
git branch --show-current       # 先确认兵种分支
git pull --ff-only origin <当前分支>  # 先同步;拒绝隐式合并
git status --short --branch     # 识别并保留他人/工具的既有改动
python tools/check_robot_scope.py     # 越界守卫:跨兵种改动 FAIL

# ── 收工提交 ─────────────────────────────
git diff -- <本次文件>          # 逐行确认兵种影响
git add <本次文件>              # 只暂存本次任务文件
git commit -m "sentry(scope): 修改说明 (DEV-YYYYMMDD-HHMMSS)"
git push origin <当前分支>
git status --short --branch
git rev-list --left-right --count HEAD...@{upstream}

# ── 看历史 ───────────────────────────────
git log --oneline -15           # 最近 15 条
git log --oneline -- config/sentry_2026/config.h     # 哨兵参数改动史
git diff HEAD~1                 # 上一次提交改了啥
```

   ```powershell

   cd RM-JIT-CR
   ```
3. **配置身份**（邮箱建议用 GitHub 的 noreply 邮箱：`GitHub用户ID+用户名@users.noreply.github.com`，在 GitHub Settings → Emails 页可查）：
   ```powershell
   git config --global user.name "你的GitHub用户名"
   git config --global user.email "ID+用户名@users.noreply.github.com"
   ```
4. **首次验证**（确认环境与仓库状态一致，三件套全过再动代码）：

## 2. 分支与提交约定

### main 是共享主干,兵种分支是烧录基线

**main 必须始终保持：三兵种都可编译、共享主机测试通过、共享层无未回流改动。**
上车固件从**当前兵种分支**(现为 `sentry`)构建,不是从 main 构建;main 上的兵种目录只随兵种分支的
`--no-ff` 合并更新,不在 main 上直接调兵种参数。

### 什么改动走哪条路

| 改动类型 | 路径 | 例子 |
|---|---|---|
| 本兵种参数级（数值/注释/兵种文档） | 在本兵种分支直接提交推送(多人并行时仍建议短分支) | 调哨兵 PID、改零位、更新 DEVLOG |
| 共享层（`components/framework/ports/tools` 等） | `fix/shared-*` → `main` → 当天 merge 回各兵种分支 | 改滤波组件默认值、修框架接口 |
| 本兵种结构级（新文件/新任务/改构建） | `<type>/<robot>/<功能>-<用户>` → **用户确认功能正常** → `--no-ff` 回兵种分支 → 删除短分支 | 加云台模块、改哨兵任务表 |
| 跨兵种或影响面不明 | **先问人**,拆成两个分支/两条 DEV 条目 | 同时动步兵与哨兵底盘 |

```powershell
# 本兵种结构级改动标准流程(以哨兵 + 张三为例)
git switch sentry                            # 先到兵种分支并同步
git pull --ff-only origin sentry
git switch -c feat/sentry/referee-ui-zhang   # 兵种/功能/用户三段命名
# ...开发、提交若干次,推送自己的短分支...
git push -u origin feat/sentry/referee-ui-zhang
# 用户台架/实车确认功能正常后:
git switch sentry && git pull --ff-only origin sentry
git merge --no-ff feat/sentry/referee-ui-zhang
git push origin sentry
git push origin --delete feat/sentry/referee-ui-zhang   # 删远端
git branch -d feat/sentry/referee-ui-zhang              # 删本地
```

分支命名：`<type>/<robot>/<功能>-<用户>`（`type` = `feat`/`fix`/`tune`/`test`;用户用 ASCII/拼音），
共享层用 `fix/shared-问题描述`。短命分支（≤1 周）**用户确认功能后**合完就删;未实测的结构级改动可先合、
DEV 标 `[待实测]`,但不得声称闭环。

### 提交信息规范

格式：`sentry(<scope>): 中文修改说明 (DEV-YYYYMMDD-HHMMSS)`，一次逻辑改动一个 commit。`scope` 推荐使用 `chassis`、`gimbal`、`shoot`、`cmd`、`config`、`build`、`docs`。

**DEV 编号(2026-11-26 起)**：`DEV-YYYYMMDD-HHMMSS`，本地时间精确到秒（例 `DEV-20261126-230716`），
避免多设备同时开发撞号；只求全局唯一，不要求时钟精准。旧的 `DEV-YYYYMMDD-NN` 是历史编号，不改写、不回收。

```
sentry(config): 小 yaw 零位按实测值修正 (DEV-20261126-201530)
sentry(shoot): 拨盘单发超时判定改为角度容差 (RM-002)
sentry(gimbal): 新增三轴分配保护 (DEV-20261126-211245)
sentry(docs): 记录哨兵弹速标定 (DEV-20261126-223007)
```

每次源码/config/构建修改必须同时更新 Markdown,至少追加 `RM_DEVLOG.md`。DEV 标题或正文中的独立“哨兵影响”字段必须显式出现 `[SENTRY]` 或“哨兵 Sentry”,并写清受影响轴、行为、验证状态和未执行项。
**调参类 commit 务必在 DEV 条目里写清实车验证结果**（如“实车确认轨迹吻合”）；未上车只能写 `[待实测]`,不得把编译通过当成实体闭环。

## 3. 每日流程

**开工**：
1. `git branch --show-current` 确认在本兵种分支,再 `git pull --ff-only origin <当前分支>` —— 同步队友的改动
2. 改动过 `apps/sentry/`、`config/sentry_2026/` 或共享 `components/framework/ports` 的,跑一遍基线审计并核对受影响文件
3. `python tools/check_robot_scope.py` 确认没有越界改动

**收工**：
1. 编译 + 主机测试通过
2. 按《RM_DEVLOG.md》格式补 DEV 条目（AI 修改的也必须写，注明 AI 模型名——AGENTS.md 契约）
3. 按 `sentry(<scope>): ...` 提交并 `git push origin <当前分支>`;确认 `HEAD...@{upstream}` 为 `0 0`

## 4. 调参标准流程（高频场景）

```
改 config/sentry_2026/config.h → 哨兵编译 → 烧录(实车操作人执行) → 实车验证
   ├─ 达标 → 回填 .Doc/spec/本车调参结论.md + RM_DEVLOG → commit(注明验证结论) → push
   └─ 不达标 → 继续改 → 重复;中间态 commit 前先 git pull 防冲突
```

- 实车标定值（零位、PID 终值）**必须当天回填**进 DEVLOG/调参结论，人记不住昨晚的数。
- 多人同时调不同子系统（底盘/云台/发射）时，都从 `config/sentry_2026/config.h` 伞头进入对应子头——**拉取要勤，改动区域错开，冲突及时喊对方**。

## 5. 冲突与撤销

**pull 冲突**：
```powershell
git pull origin <当前分支>
# 冲突文件会用 <<<<<<< ======= >>>>>>> 标出,和队友当面确认保留哪边
# 编辑完成后:
git add <冲突文件>
git commit                      # 完成合并
git push
```

**撤销操作**（按状态选，别猜）：

| 状态 | 命令 | 说明 |
|---|---|---|
| 改了还没 add | `git restore <文件>` | 丢弃工作区改动，**不可恢复** |
| add 了还没 commit | `git restore --staged <文件>` | 取消暂存，内容还在 |
| commit 了还没 push | `git reset --soft HEAD~1` | 撤 commit，改动保留 |
| 已经 push 到远端 | `git revert <commit-id>` | 生成反向提交，**安全** |

> ⚠️ **严禁** `git push --force` 到 main、严禁 push 后 `reset --hard` 再推——会吃掉别人的提交。实在要回滚远端用 `git revert`。

## 6. 禁令（对齐 AGENTS.md，违反会被要求回滚）

- 不提交：`build/` 固件产物、`.elf/.hex/.map`、大文件（视频/压缩包，>50MB 联系管理员走网盘）
- 不改：`Drivers/`、`Middlewares/`、`Src/Inc/` 的 USER CODE 区外代码、`basic_framework.ioc`（需明确批准）
- 逻辑层 `apps/sentry/` 不直接碰 `hcan*/husart*` 等硬件句柄，一律经模块实例
- 任务启停只用 `robot_task.h` 宏，不注释启停
- 新增 .c 文件必须同步登记 Makefile
- `git push --force`、删除远端分支、改写他人提交：禁止(唯一记录例外：2026-11-26 `sentry` 分支重建,
  已先打标签 `sentry-legacy-20261126` 备份,见《.Doc/spec/兵种分支协作规范.md》§10)

## 7. CI 自动构建

推送到 main（或开 PR）后，GitHub Actions 自动执行：`make` 全量构建 + CMake/Ninja 构建。
绿勾 = 两套构建系统都编译通过；红叉 = 去 Actions 页看日志，**CI 红着不要往 main 合结构级改动**。

## 8. FAQ

**Q：push 被拒 `remote rejected ... fetch first`？**
A：队友先推了新提交。`git pull` 再 `git push`。

**Q：不小心把 build/ 或大文件 commit 了？**
A：还没 push → `git reset --soft HEAD~1`，把文件从暂存区去掉重提；已 push → 喊管理员处理，别自己 force push。

**Q：commit 写错字/漏文件？**
A：还没 push → 改完 `git add` 后 `git commit --amend`（覆盖最近一次提交）；已 push 就追加一个新 commit，别 amend。

**Q：报错 `CMakeCache.txt directory is different` / `source does not match the source used to generate cache`？**
A：`build/` 缓存里写死的是绝对路径,工程文件夹挪过位置(或改名)就会对不上。**删掉整个 `build/` 重新配置即可**,里面全是可重新生成的产物:
```powershell
cmake -G Ninja -B build && ninja -C build
```
从 git 克隆不会带 `build/`,此问题只在本机移动工程文件夹时出现。

**Q：想看某个哨兵参数的调参历史？**
A：`git log -p -- config/sentry_2026/config.h | less`，或 GitHub 网页上打开该文件点 History。
