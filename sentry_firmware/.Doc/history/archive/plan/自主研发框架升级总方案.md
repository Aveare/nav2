### 3.2 依赖规则(传递闭包扫描,§11-A2)

`apps→components→framework→ports→HAL`。framework **零平台 include,消费 3 类 port 供给**:①kernel(临界区/时间——DWT 由 ports 实现 `kernel_time_us`,DWT_Init 用 SystemCoreClock 派生而非写死 168);②diag 存储(遥测 arena 注入);③log sink(RTT 是 port 的 sink,framework 只保留 %f 禁令纯解析器)。扫描按 `gcc -M` 闭包:**framework/ 一律 0 个 RTOS include(FreeRTOS.h/task.h/cmsis_os.h),FreeRTOS 后端唯一落点 ports/freertos**;含 main.h 的必须在 ports;存量豁免清单只减不增。**登记例外**:referee_task.c:14-15 反向 include(B6 消除)。

### 3.3 两层装配(铁律:同一件事只能一层决定)

- **编译期**(profile.h 顶部 `#define`):只裁剪不参与链接的可选组件,命名 `<MODULE>_<ENABLE>`;`#if` 只允许出现在 profile.h 内,每项登记 B 类账本。
- **运行期**(`static const assembly_t`):组件实例、任务频率、总线实例分配、板型;所有"可不重编就改"的项进此表。
- 板型为**三值**(ONE_BOARD/CHASSIS_BOARD/GIMBAL_BOARD);B8 保留编译期选择(彻底零行为),运行期字段化推迟到 B11(若做,入白名单)。

### 3.4 迁移命名表

迁移 = 只改目录前缀不改文件名;include 路径变更属"路径改写",G6 清单逐文件声明;搬移文件保留原文件头(G6 兼容),实现替换批(B5/B6)统一更新署名(附F.1)。

## 4. 核心契约要点(B1 定稿随框架头携带;细节=审查 B 域报告)

- **kernel**(§T05):15+3 原语;**必须补** `kernel_is_in_isr/current_task/start`(msg 单写者检测、ISR 断言、启动接线的硬前置);优先级数值钉死+静态断言;`configASSERT` 改 err_report(FreeRTOSConfig.h:135 的 for(;;) 是 grep 盲区);freertos.c defaultTask/USB init 处置进附B。**放置:API 头在 framework/kernel(平台无关),FreeRTOS 后端实现归 ports/freertos——framework 不出现任何 RTOS include。**
- **bus**(§T06):发送**定死 TX 邮箱 ISR 续传**;满丢最老**必须计数+日志限流 1/100ms**;AddTxMessage 失败=帧留队列(邮箱空中断续传)的窗口语义;`tx_id` 晚绑定(GM6020 模式切换依赖)为不变量;filter bank 14/总线预算+ConfigFilter 返回值必查;伪实例→`bus_tx_frame`(仅 tx_id+payload);总线数=2 显式拒绝第三条;**解码回调保持在 ISR**(现状),单帧到回调延迟=0 拍为契约。
- **msg**(§T04):`msg_publish` 非 ISR——首行 `kernel_is_in_isr()` 断言(drop_cnt++/调试构建 configASSERT);适配头保留"返回 1";话题上限 8(实施检查,替换死宏 MAX_TOPIC_COUNT);深度>1 为新能力不进零行为声明;**B7 与 B2 相邻执行**(生产调用点 25 处只改一遍)。
- **err**(§T02):四档**分投递**——LOG_ONLY=计数+lock-free 环(ISR 安全,diag 任务取走打印,限流 1 条/100ms/错误码);SAFE_STATE=只置原子标志,**RobotTask 首拍消费**执行注入回调(ISR 写任务数据面=双写者,禁止);RESTART=待重启位;FAILFAST_BOOT 才直接 FaultRecord。临界区内禁 err_report(仅 deferred)。错误码高字节入 BKP0R 低 8 位,与蜂鸣码映射表固定。
- **diag**(§T03):必活/可选集合(见 T03);daemon 并入但**超时单位=拍数**为不变量(节拍源与迁移前一致);遥测改 **arena 注入式**:ports/stm32f4 定义 5 环对象(`.ccmbss+aligned(8)`),framework 拿指针——框架零段宏、主机测试可指向任意缓冲;`TELEMETRY_LOG_DIV` 过渡期 100→200(RTT 预算)。
- **宏账本**(§T14/附D):五类 + derived_from/injected 属性;A 类规则=**依赖闭包内不得含 B 类宏**(纯 `?:` 语法不可判定,PITCH_GRAVITY_FF_LIMIT 是反例);死三元式(两支同值)检测;查重(附D)。

## 7. 协作与插队纪律

### 7.1 双线模型(队友继续调自瞄场景)
`main`=始终可烧录可参赛(队友自瞄调试/调参/实车验证在此,照常 push);`framework` 批次分支=架构工作,每批过闸门合回 main 打标签 `arch-after-<batch-id>`。**合入窗口=批间隙**:批开工前先合 main 最新→用上批 tag 生成 G4 manifest(本地 `save-baseline` 只作缓存)→开工;批进行中队友提交不合入(G4/G1' 会误判)。三类情形:调参=批间隙合入+DEV;USART1 交接(AX650_UART1_ENABLE 0→1)=B 类开关变化,批间隙+DEV,不需暂停;新增功能=插队流程或 M3 后。

### 7.2 插队三硬规则(从 11-21 插队冲掉基线的事故中提取)
1. 插队前当前批必须推进到**可编译/可烧录/闸门全绿**的提交,打 `arch-pause-B{n}`;未到可编译状态默认拒绝。
2. 插队改动触碰本批迁移文件 → 恢复后该批 G5 基线作废,重锚+整批重跑;DEV 写明被插队改过的文件。
3. 插队期间功能改动=临时解冻,须用户单独批准;产生行为变化必须补进 §5 白名单并补验证,否则不得进入迁移基线。

### 7.3 比赛硬日期断路器

- 批准档二时必须在 §0.4 填写 **T_season = 最晚 B8 过闸日期**;未填写视为只批准档一,不得启动 B5/B6/B8。
- 若 **T_season − 4 周**时 B8 仍未过闸:立即打 `arch-pause-B{n}`,停止新迁移批,功能轴解冻;比赛/训练只用 `main` 上最后一个闸门全绿的 tag。
- 若 B8 已过但 M3 未完成:在 **T_season − 2 周**冻结结构轴,只允许 M3 缺陷修复,不再开 B11/B12 的结构工作。
- T_season 变更必须由用户书面确认并记 DEV;不得用“可停可弃”的性质描述替代日期触发。
