# 常见故障排查(现象 → 证据通道 → 处置)

> 组织方式:每条 = 现象 / 证据通道(先取证再动手) / 处置 / 易错点。
> 与《调参诊断手册》分工:那边管"参数往哪调",这边管"车不正常怎么办"。
> 上位经验与历史结论:`.Doc/robots/infantry/params/调参结论.md` §踩坑、当前兵种 `DEVLOG.md` 问题台账。

## 1. 上电/复位类

| 现象 | 证据 | 处置 |
|---|---|---|
| 上电无日志、无蜂鸣 | doctor.js(固件身份/供电) | 烧录未生效:核对 download 任务与 ELF;固件身份不匹配=旧固件在跑 |
| 一长声 | `[boot] RST cause: POR/BOR` | 正常上电/掉电;若运行中突发=电源问题(查供电/接触) |
| 两短声 | `SW=1` | 烧录后正常复位 |
| 三短声 | `IWDG=1` + `[diag] required task dead [X]` | 任务 X 卡死;按名字定位(1kHz 超期日志/死循环/阻塞调用);G9 注入可复现验收 |
| 四短声 | `fault_consume()` 非 0 | HardFault:复位前详情由 `fault_dump_to_uart()` 打到 USART1,按 CFSR/BFAR/PC 定位 |
| 五短声 | StackOverflow | 任务栈溢出;加大对应 `stack_words`(INS/ROBOT 1024 基线) |

## 2. 任务/调度类

| 现象 | 证据 | 处置 |
|---|---|---|
| 某任务反复 DELAY 日志 | `[freeRTOS] X Task DELAY dt=..us` | 注意**日志数值是 µs 但标签含 ms 字样**(robot_task 注释陷阱);按 µs 解读,超时预算 INS/MOTOR 1ms、DAEMON 10ms、ROBOT 5ms |
| 看门狗 2s 复位循环 | `[diag] required task dead` 名单 | 必活集合 {INS,MOTOR,ROBOT,DAEMON} 任一失活;UI 不在必活(UI 合法永久不活) |
| 上车即 ROBOT_STOP 不解锁 | RTT | 解锁条件=右上挡+左中挡+全杆回中;`cmd_authority` 锁存任一停止来源 |

## 3. 通信类

| 现象 | 证据 | 处置 |
|---|---|---|
| 遥控失联/误断流 | `[rc]` 日志 + daemon | DBUS 18B 无帧头,丢 1 字节无法自愈 → 帧校验拒绝(清零+不喂狗);断流 200ms 阈值勿随意放宽 |
| 裁判系统无数据 | `referee_recv_info->init_flag`/`[heat]` OFF;先看 `YAW_AUTO_VOFA_USART6_ENABLE` | 该宏=1 时 USART6 归自瞄 yaw VOFA,裁判数据和 UI 会暂停;比赛/热量守卫配置必须回 0 |
| 视觉链路无 0x0503 | `[ax650]` + `AX650_UART1_RX_ENABLE` | 两级开关:总开关/RX 分开;错误组合编译期 #error |
| CAN 收不到某 ID | 丢帧计数 + `can_add_filter` | 拨码号≠组帧 ID(见 code-map 组帧规则);bank 分配/奇偶 FIFO |
| CAN 发送堆积 | TX 丢帧计数 | 满丢最老+限流;查 1kHz 是否被拖慢 |
| 系统 VOFA 无波形 | USART1 归属 | `CHASSIS_VOFA_UART1_ENABLE=1` 且 AX650=0;接线 RX 接 PA9、共地、勿 5V |
| 自瞄 VOFA 无波形 | USART6 归属 | `YAW_AUTO_VOFA_USART6_ENABLE=1`;VOFA 115200 8N1,只输出自瞄相关量 |

## 4. 执行器类

| 现象 | 证据 | 处置 |
|---|---|---|
| 电机反馈正常但不出力 | `motor_health` 预设 | 电流模式 0x2FE:**先查 RoboMaster Assistant"电流环"开关**(RM 台账定案,同一代码电压出力/电流零扭矩) |
| 云台疯转 | 反馈源 | 云台电机必须 OTHER_FEED(IMU);编码器反馈=错误源 |
| 拨盘堵转锁死 | `LOADER_JAM_*` | 锁存解除=拨轮回中且无待发弹;勿用断电复位掩盖 |
| 摩擦轮不转 | RTT 互锁 | 到速互锁未满足(`FrictionReady` 容差 `SHOOT_FRICTION_READY_TOL_RPM`) |

## 5. 记录纪律

- 每次故障:现象 → 证据通道输出(粘贴) → 处置 → 结论写当前兵种 `DEVLOG.md`(问题台账或 DEV)。
- 同一现象第二次出现必须升级为台账条目(防"修过又忘")。
- 台账关闭需要"可证伪证据"(日志行/遥测 CSV/实车确认),不接受"应该是好了"。
