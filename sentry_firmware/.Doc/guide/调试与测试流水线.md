# 调试与测试流水线

> 目标:把"改代码 → 验证 → 上车 → 采集证据 → 收工"固化成一条**每步有工具、有产物、有退出判据**的流水线。
> 原则:①能在主机做的绝不留到车上;②上车先 smoke 再调参;③读数优先非侵入式(不暂停核心);④每个结论带证据等级。
> 配套:`tools/README.md`(工具速查)、`调参诊断手册.md`(症状→参数)、`常见故障排查.md`(现象→处置)。

## 1. 流水线总览

```
改动 → [静态闸门] → [主机测试] → [ARM 编译] → 烧录 → [smoke] → [采集/调参] → 收工(DEV+提交推送)
```

| 阶段 | 命令 | 退出判据 | 产物 |
|---|---|---|---|
| 静态闸门 | `python tools/check_naming.py` / `check_macros.py` / `check_macro_dups.py` / `check_macro_golden.py` / `check_abi_golden.py` / `check_comment_style.py` / `check_build_parity.py` / `check_symbol_contract.py` / `check_source_lists.py` / `check_sections.py` | 全 exit 0 | 控制台输出 |
| 主机测试 | `powershell -File tests\run_chassis_tests.ps1` / `run_fwk_tests.ps1`(含探针/ABI/注释/parity/profile/can 金标准/整链对拍) / `run_ax650_tests.ps1` | exit 0 | tests/build/*.exe |
| ARM 编译 | `cmake -G Ninja -B build && ninja -C build`(多兵种:`-DROBOT_PROFILE=<robot> -B build_<robot>`) | 0 error/第一方 0 warning | build/*.elf + size |
| 烧录 | VSCode tasks `download_dap` / `download_jlink`,或 `mingw32-make download_*` | 烧录器确认 | — |
| smoke | 双击 `tools\capture_rtt.bat` 常驻抓 RTT → `python tools\smoke_check.py log\_console.log` | 启动标记在、禁用标记无 | 结论行 |
| 采集 | `node tools\pitch_trace.js --preset <名>`(EmberProbe 后台采样) | CSV 落盘 | build/trace_*.csv |
| 离线分析 | `python tools\analyze_var_trace.py <csv> --all` / `motor_calib.py` | 三态判据/标定初值 | 结论进 DEV |
| 收工 | RM_DEVLOG DEV 条目 + git commit + push | push 成功 | commit SHA |

## 2. 三条铁律(历史事故换来的)

1. **运行期禁止 memory.read / debug.evaluate 读参**——会暂停核心几十 ms,C620 约 100ms 无帧
   按 0 输出,枪管被重力砸下去,你看到的"现象"是探针造成的(DEV-20261112 实测)。
   读变量一律走 EmberProbe `variables.sample`(后台 DAP 采样)或 RTT 日志。
2. **两套读数通道不要同时占探针**:EmberProbe(VSCode 扩展)与 `rtt_read.py`/Ozone 互斥;
   排查"读不到数"先跑 `node tools\doctor.js`(按桥接→进程→会话→固件身份→供电→指针顺序)。
3. **烧录后第一件事是 smoke,不是调参**:`smoke_check.py` 看到 `[boot] RST cause` 与五个
   `Task Start` 再动手;蜂鸣码(1 长/2~5 短)是人不在电脑前时的备份通道。

## 5. RTT 日志速查(结构化标记 → 含义)

| 标记 | 来源 | 读法 |
|---|---|---|
| `[boot] RST cause: IWDG=..` | robot 复位原因 | IWDG=1 表示上轮看门狗复位;配合蜂鸣码 |
| `[freeRTOS] X Task Start` | 各任务启动 | 5 个任务(INS/MOTOR/Daemon/ROBOT/UI*)少一个=接线问题 |
| `[diag] required task dead [...]` | 心跳监督 | 停喂 IWDG,2s 内复位;名字即卡死任务 |
| `[err] code=0x.. tick=..` | err 排水 | 错误码高字节进 BKP,蜂鸣码映射 |
| `[heat] ...` | 热量守卫 1Hz | 状态 OFF/NORMAL/SINGLE/HOLD + 摊平射速 |
| `[chcal]` | 底盘标定 | 功率/缓冲能量 -1 = 裁判未上线 |
| `[ax650]` | 视觉链路 | init failed → INS 重试路径 |

浮点打印纪律:RTT 不支持 `%f`,一律 `log_float_to_str()` 后 `%s`(check_log_format.ps1 守卫)。

## 6. 非侵入式读参速查

```powershell
# 症状预设采集(推荐入口;预设见 tools/trace_presets.json)
node tools\pitch_trace.js --preset yaw_oscillation
node tools\pitch_trace.js --preset pitch_stutter --label 中挡自稳
node tools\pitch_trace.js --preset chassis_follow --seconds 30

# 自定义变量(任意 DWARF 路径;契约由 check_symbol_contract 守卫)
node tools\pitch_trace.js --vars "gimbal_imu_data->YawTotalAngle,yaw_motor->measure.speed_aps" --seconds 20

# 离线判据(振荡/静止/慢漂三态)
python tools\analyze_var_trace.py build\trace_yaw_oscillation.csv --all

# 电机速度环标定(离线拟合,输出 Kp/Ki 初值)
python tools\motor_calib.py build\x.csv --target vt_lf --speed "motor_lf->measure.speed_aps" --u "motor_lf->measure.real_current"
```

不接 EmberProbe 时:`tools\rtt_read.py`(独立 OpenOCD 路径)或 `JlinkRTTClient`;
Ozone live watch 读 telemetry 五环(`telemetry_*`,CCMRAM)是第三条通道。
