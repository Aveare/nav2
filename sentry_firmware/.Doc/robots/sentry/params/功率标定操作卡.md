# 哨兵功率标定操作卡(台架用)

> 依据:DEV-20261128-050643(功率控制对齐步兵 + 采集工具)、DEV-20261128-<spin>(联合采集与运行期自转速度)。
> 协议沿用步兵实车沉淀:**一次一工况、20s、开采有提示、先存 CSV 不分析、全采完再拟合**。
> 真实功率机器人拿不到(0x0202 已无功率反馈):从**裁判客户端或台架电源**读稳态读数,事后补进 CSV。

## 0. 一次性前置

1. `.\build.ps1 sentry -Current` → 烧录 `firmware/sentry.elf`(EmberProbe 或 `tools/flash_manual.ps1`)。
2. 固件带 `CHASSIS_CALIB_LOG=1`(RTT 2Hz 输出 `[chcal]/[pwri]/[pwr]`)。
   **`CHASSIS_POWER_CTRL_EN` 现为 1**(DEV-20261128-055920:打开限幅修"哨兵 id 断电",
   目标功率 = 裁判上限 − 8W)。注意两种状态的用途:
   - **验证限幅行为/复测断电**:保持 CTRL_EN=1 直接采,`[pwr]` 的 s/lim 列就是要看的数据;
   - **重拟合 K0..K5**:拟合只收 s≥0.99 的点(限幅生效时指令电流≠实际电流),需临时把
     `CHASSIS_POWER_LIMIT_MAX/DEFAULT` 抬到 200(或 MARGIN 拉大)保证 s=1,采完改回。
3. 探针连好,RTT 可读(`tools/capture_rtt.bat` 或 EmberProbe mcu-rtt)。
4. 自转速度运行期可调:`sentry_rt_rotate_speed_dps`(默认 = `CHASSIS_ROTATE_SPEED` = 300 deg/s),
   用 EmberProbe 变量写改,**不重烧**;|值|<30 或 >600 自动回退 config。

## 1. 每次台架三步

```powershell
# ① 秒级体检(全部 PASS 才继续;FAIL 行有明确处置提示)
python tests/sentry/power_capture.py doctor

# ② 采一个工况(默认 20s;提示后保持工况,同时读稳态功率记下来)
python tests/sentry/power_capture.py capture <工况名>

# ③ 换工况重复 ②;全采完统一拟合
python tools/fit_power_model.py steady_raw.csv --out build/power_model_snippet.h
```

## 1b. 小陀螺联合采集(功率 + 大yaw/小yaw 稳定性,一条命令两路数据)

```powershell
# 先把自转速度写到目标值(变量写,不重烧),再:
node tests/sentry/spin_capture.js --label spin300 --secs 20
```

一次 20s 窗口同时落盘:
- `log/<label>_20s.log` —— RTT 文本含 `[pwri]/[pwr]`,事后
  `python tools/rtt_pwr_to_csv.py log/<label>_20s.log --power <W> --append steady_raw.csv`;
- `log/<label>_20s_yaw.csv` —— world_deg/world_spd/torque/spd_tgt/small_joint/small_ref/
  fric_ff/carrier_inj/est_wz/mode/rearm/active,50Hz;
- 终端直接给摘要:进入 3s 拖拽(判据 <10°)、稳态 |世界角速度|(判据 <2°/s)、力矩均值、卸力拍占比。

变转速工况:改 `sentry_rt_rotate_speed_dps`(如 400/500)→ 重复上面的联合采集,label 带转速。

## 2. 工况表(建议覆盖)

| 工况名 | 操作 | 目的 |
| --- | --- | --- |
| `static` | 底盘使能、零指令静止 | K0 常数项底 |
| `v500` / `v1000` / `v2000` | 纯平移三档稳态 | 一次项/平方项 |
| `spin300` | 纯自转(现行 ROTATE_SPEED) | 自转工况(对应"断电复测")+ yaw 稳定性基线 |
| `spin300v1000` | 自转+平移组合 | 交叉项 K3 |
| `spin400`/`spin500` | 变转速(运行期变量) | 自转速度-功率/稳定性曲线 |

稳态判定:客户端功率波动 <2W 再算稳态;每工况日志独立(`log/<工况>_20s.log`)。

## 3. 拟合与回填

1. 把每工况读到的稳态功率填进 `steady_raw.csv` 对应行 `p` 列。
2. `python tools/fit_power_model.py steady_raw.csv --out build/power_model_snippet.h`
   (自动丢弃 s<0.99 的行;CTRL_EN=0 时 s 恒 1 全有效)。
3. 回填 `config/sentry_2026/config_chassis.h` 的 `CHASSIS_POWER_MODEL_K0..K5`,
   **同时核对 `LIMIT_MAX/LIMIT_DEFAULT/BUFFER_MIN_SCALE`**——只改 K 不改上限会把限幅判错。
4. 回填后 `CHASSIS_POWER_CTRL_EN` 置 1 重编译重烧,复测全包线(自转+平移),观察 `[pwr]` 的 s/lim/be。

## 4. 排障速查

| 现象 | 处置 |
| --- | --- |
| doctor:PROFILE≠sentry / SHA 不一致 | 别的兵种构建覆盖了 `current.elf`;重跑 `build.ps1 sentry -Current` 再核对 |
| doctor:RTT 不可读 | 先跑 `tools/capture_rtt.bat`(或 mcu-rtt --start);探针没上电/没插也会这样 |
| doctor:没有 [pwri] 行 | 板上固件是旧的(无标定日志),重烧 `firmware/sentry.elf` |
| 采完 0 对样本 | 日志里没有成对 [pwri]/[pwr];确认固件是新烧的、工况期间没断 RTT |
| 提示 s<0.99 | 限幅在生效,该点不能用于拟合;回 CTRL_EN=0 或临时抬 LIMIT_MAX |
| 缓冲 be<10J | 先让缓冲回充再采下一点 |
