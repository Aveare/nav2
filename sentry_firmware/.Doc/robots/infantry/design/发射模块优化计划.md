## 0. 一句话结论

发射模块缺的**不是算法,是三个标定和一个恢复机制**:
①转速→弹速曲线从未标定(4000 RPM 是"3000 不足、5000 过快"之间的猜值);
②`ONE_BULLET_DELTA_ANGLE` 按名义槽数算,回差与过冲未实测;
③堵转阈值 1800 码 / 30 rpm / 500 ms 从未做过台架实验;
④卡弹后**锁存等人工解除**,而开源普遍有自动反转退弹。

其中**转速稳定性要先订正数量级**:北科开源文档的「转速 ±5 rpm → 弹速 ±0.5 m/s」按物理上限
(dv/d(rpm) = 轮半径 × 2π/60 ≈ 0.003~0.004 m/s/rpm——弹速不可能超过轮面速度)推算,±5 rpm 只对应
±0.02 m/s,**原句疑似转写错误(可能是 5% 或 500 rpm),引用前回源核对**。
按物理换算的修正结论:`FRICTION_READY_TOL_RPM = 500` 确实对应 ±2 m/s 量级的散布潜力(值得收紧),
但 ±50 rpm 的稳态波动只有 ±0.2 m/s(≈1%),不构成弹道灾难——判据按此重定,别把 P2 卡在一个物理上过严的数字上。

## 1. 现状基线

### 1.1 控制链

```
摩擦轮 ×2(M3508+C620, CAN2 ID1/ID2;**方向已反转:REVERSE 在左轮,见 P0-5**)
   → 速度环,目标 FRICTION_TARGET_RPM=4000(速度环 MaxOut=6000,电流环占位 MaxOut=15000)
   → 到速判定:双轮在线 + |实测−目标| < FRICTION_READY_TOL_RPM(500)

拨盘(M2006+C610, CAN2 ID3, 36:1)
   → 连发:速度环,目标 = shoot_rate × ONE_BULLET_DELTA_ANGLE × 36
   → 单发/三发:待发弹数状态机,逐发**角度环**推进,到位容差 LOADER_ANGLE_TOL_DEG=6°,
      超时 LOADER_SINGLE_TIMEOUT_MS=1000
   → 堵转:转速<30 rpm **且** 电流≥1800 码,累计 500 ms → 停盘锁存

单发角 ONE_BULLET_DELTA_ANGLE = 360 / NUM_PER_CIRCLE(7 槽 → 51.43° 输出轴)
```

## 3. 本车问题归因

### 3.1 弹速从未标定,`FRICTION_TARGET_RPM` 是猜的

现有结论是"3000 弹速不足、5000 过快",取中间 4000。这只能说明 4000 在可用区间,
**不知道 4000 对应多少 m/s、也不知道 ±500 rpm 会造成多大散布**。

按物理换算(dv/d(rpm) = r×2π/60,r≈3~4cm → 0.003~0.004 m/s/rpm;弹速不可能超过轮面速度):
- ±50 rpm 的稳态波动 → 弹速散布约 ±0.2 m/s(≈1%),**不致命**;
- `READY_TOL=500 rpm` 的到速容差 → 贴着容差边界开始拨弹时散布可达 ±2 m/s(≈10%),**这才是大头**;
- 带弹瞬间轮速被挤压跌落、速度环恢复的快慢,决定连发的弹速一致性(P2 逐发测)。

所以第一个要测的仍是"4000 时转速稳不稳"(P1-B3),但判据按物理重定(±50 rpm),不是北科转写值。

### 3.2 拨盘 40% 空载需手推 → 机械阻力异常

`MaxOut=8000`(80%) 是为了让低占空比能起动。但**空载(不装弹)都起不动**,
说明阻力来自:拨盘与弹仓的同心度、弹链/软管的预紧、齿轮啮合过紧、或 C610 的电流环标定。

**用提高限幅来掩盖机械阻力是危险做法**:真正卡弹时,80% 限幅意味着更大的挤压力,
弹丸被压扁、拨齿被打坏的概率更高。

### 3.3 "2400 一发后卡弹"可能是过冲推了两颗

单发用**角度环**推进,到位容差 6°(输出轴)。7 槽时每发 51.43°,容差 6° 相当于 11.7% 的槽距。

如果角度环有过冲(尤其 Kd 不足或积分饱和),实际转过 57°→ 拨齿已伸入下一槽 → 第二颗弹被顶到
摩擦轮入口但没人推 → **卡在入口**。这与"一发后卡弹"的现象完全吻合,**而降速到 2000 只是
减缓了过冲速度,症状被掩盖而非解决**。

### 3.4 堵转判据太慢,且需要两个条件同时成立

```c
if (|speed| < 30 rpm && |current| >= 1800) loader_jam_ms += dt;
if (loader_jam_ms >= 500) 停盘锁存
```

三处可疑:
- **500 ms 太长**:堵转时弹丸在拨齿与枪管间被挤压,500 ms 足够把弹压变形;
- **双条件 AND**:若电机堵转但电流尚未升到 1800(比如驱动能力不足),永远判不出来;
- **阈值 1800 码无依据**:C610 满量程 10000,1800 = 18%,对 M2006 + 36:1 来说可能偏低。

ACE 哨兵的做法是**纯电流法**:限幅 9000,反馈 >8800 判堵转。0.1 s 级就能判出。

### 3.5 卡弹后无自动恢复

锁存后必须松拨轮——这在比赛里意味着**一次卡弹 = 这个回合报废**。
开源普遍做法是"检测到堵转 → 反转一个槽距 → 再试一次",失败才锁存。

### P2 转速→弹速标定(核心,≈2 小时,需测速仪或高速摄像)

**方法**:固定 pitch=0、距枪口 **2~3 m** 处放测速仪(240fps 测 1 m 飞行时间的误差约 ±8%,
即 20 m/s 时 ±1.7 m/s——精度不足以支撑 σ<0.5 m/s 的判据;慢动作方案要拉长基线并侧向拍摄已知标尺)。
**弹丸用同一批次**(弹丸公差直接进入散布)。

1. `FRICTION_TARGET_RPM` 取 3000 / 3500 / 4000 / 4500 / 5000 五档;
2. 每档打 **10 发**,记录每发弹速;
3. 拟合 `v = k · rpm + b`;
4. **同时记录**:每档转速峰峰值、双轮转速差 `fl−fr`、**每发挤压瞬间的轮速跌落深度与恢复时间**、连发第 1 发 vs 第 10 发的弹速差。

**判据**:
- 线性度 R² > 0.95(否则说明有非线性机制,如打滑)
- **同档 10 发的弹速标准差 < 0.5 m/s**(按物理换算对应转速波动约 ±120 rpm——这才是转速稳定性的真实需求)
- 连发第 1 发与第 10 发弹速差 < 1 m/s(否则说明包胶升温影响显著)

**产出**:`FRICTION_TARGET_RPM` 按下式反解 —— 目标弹速 `v_target` 由弹道需求定
(与 pitch 补偿联动),`rpm = (v_target − b) / k`;
**同时按实测峰峰值重定 `FRICTION_READY_TOL_RPM`**(现为 500,贴容差边界拨弹的散布潜力 ±2 m/s,
是弹速散布的大头;新值 = 转速波动实测峰峰值 × 2~3 倍余量,标定前无法拍脑袋收紧)。

> 若测不了弹速:**退化为"相对标定"**——只测"哪一档最稳"(10 发离散度最小),
> 不追求绝对值。这比现在"4000 感觉可以"强,但要在文档里标注 `[待实测-绝对值]`。

### P3 拨盘单发精度(≈1 小时)

1. 按 B5/B6 的结果修正 `ONE_BULLET_DELTA_ANGLE`(用实测值,不用 360/7);
2. **测过冲**:单发指令下,记录拨盘转角的时间曲线(用 `[shootcal]` 或 Ozone),
   看是否有"冲过目标再回来";
3. 若有明显过冲:先降角度环 Kp / 加 Kd;仍不行再考虑"到位前减速"(位置-速度两段式)。

| 判据 | 目标 |
|---|---|
| 单发转角误差 | <3°(输出轴) |
| 7 发累积误差 | <5°(不累积) |
| **无过冲** | 转角曲线单调趋近,不越过目标后回退 |
| 无"推两颗" | 连打 10 发,**弹仓计数每发减 1** |

**回退**:恢复名义 51.43°,过冲问题回到"降速到 2000"的旧方案。

### P4 堵转检测与自动恢复(≈1.5 小时)

**P4-0 台架堵转实验**(必须先做,否则阈值仍是猜的):

1. 拨盘装弹,人为卡住(或用夹具);**每次堵转 ≤0.5 s、间隔冷却**,防烧电机;
2. 记录堵转瞬间的:电流上升曲线、转速下降曲线、**弹丸开始变形的时刻**;
3. **对照组:正常连发时每颗弹过拨齿的电流脉冲幅值/时长**——纯电流判据(80~150 ms)必须不被这些脉冲触发,否则误判;
4. 据此定三个数:电流阈值、判定时间、以及"多久必须停机"。

**P4-1 改成电流主判据**:

```c
/* 现状:双条件 AND + 500 ms */
if (fabsf(speed_rpm) < LOADER_JAM_SPEED_RPM && fabsf(cur) >= LOADER_JAM_CURRENT)
    jam_ms += dt_ms;

/* 建议:纯电流,时间缩短 */
if (fabsf(cur) >= LOADER_JAM_CURRENT_NEW)      // 由 P4-0 定,预期 6000~8800 码
    jam_ms += dt_ms;
if (jam_ms >= LOADER_JAM_HOLD_MS_NEW)          // 由 P4-0 定,预期 80~150 ms
    → 触发 P4-2
```

**P4-2 自动退弹**(`LOADER_BACKOFF_EN=1` 时启用):

```
检测堵转 → 反转 1.2 个槽距 → 停 100 ms → 重试正转
         → 若 2 秒内再次堵转 → 才锁存并报警
```

> **退弹必须与待发队列状态机联动**(计划原文漏了):`loader_pending`/`loader_step_active`/本发目标角
> 要同步回退或清零;单发与三发的回退语义不同(三发退弹后是"重试当前发"还是"整队作废"要先定义)。
> `[shootcal]` 加一列退弹事件,便于统计成功率。

| 判据 | 目标 |
|---|---|
| 判定时间 | <150 ms(弹丸无明显变形) |
| 误判率 | 正常连发 200 发内误触发 0 次 |
| 自动恢复成功率 | 人为制造 10 次轻卡,**≥7 次能自动恢复** |
| 锁存兜底 | 重试 2 次仍失败必须停,不能无限重试 |

**回退**:`LOADER_BACKOFF_EN=0`,恢复锁存。

**P4-3 摩擦轮卡弹检测**(新增功能,这是 P6"摩擦轮堵转 200 ms 停轮"判据的实现落点,原计划没有安排):
摩擦轮被弹丸顶死目前无任何检测。做法与拨盘堵转同构:双轮 `|real_current|` 超阈值(由 P4-0 同批台架数据定,
注意 M3508 速度环 MaxOut=6000,阈值不得高于它)累计 ~200 ms → 停双轮并报警。
判据:人为卡轮 200 ms 内停轮;正常连发 200 发内误停 0 次。

### P5 连发与热态补偿(≈1 小时,可选)

依据 ACE 哨兵的做法:**连续发射会让包胶升温 → 弹速上升 → 有超射速锁发射的风险。**

1. 连发 20 发,记录弹速随发数的变化(每发一次);
2. 若第 20 发比第 1 发快 >2 m/s:加"热态补偿"——按连发发数或累计发射量,适当下调目标转速;
3. 判据:连发 20 发全程弹速波动 <2 m/s。

> 本车是步兵(单发/三发为主),热态效应可能不显著。**先测,数据不支持就不做。**

### P6 安全与热量(≈40 分钟)

| 项 | 判据 |
|---|---|
| 摩擦轮堵转(卡弹顶死) | 电流超限 200 ms 内停轮 |
| 单发超时 | 1000 ms 未到位必须停,不能一直顶 |
| 热量 | 连发 20 发后枪管温度 <60℃;摩擦轮电机温度 <70℃ |
| 裁判热量上限 | 单发/三发各档的 `heat` 增量实测,与裁判 UI 对照 |

### P7 回归与归档(≈1 小时)

单发 10 次 / 三发 5 次 / 连发 2 s × 3 次 / 人为卡弹 3 次,全部通过后:
结论写入 `.Doc/robots/infantry/params/调参结论.md` §5、`.Doc/robots/infantry/params/参数证据表.md`、`RM_DEVLOG.md`。

| 风险 | 触发 | 表现 | 处置 |
