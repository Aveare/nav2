## 0. 一句话结论

底盘的优先级**不是调参,而是补三块功能**,顺序由"丢分风险"决定:

```
功率控制(P2)  >  速度估计(P1)  >  滑移补偿(P5)
```

因为超功率 → 缓冲能量耗尽 → **裁判直接断电**,是一局比赛里最硬的一种失败;而功率控制的前置阻塞是
**0x0202 功率字段压根没解析**(结构体里写成 `reserved3`),所以 P0 必须先修协议解析。
速度估计既是功率模型与滑移补偿的基础,也正好用来验证 11-12 刚修正的几何量(500×460 / 力臂 340)。

## 3. 本车的问题归因

### 3.1 功率控制 = 全空,而不是"调得不好"

`motor_task.c` 明确注释"本车未接裁判/超电,`PowerControl()` 暂不调用";而 `PowerControl()` 本体是
跃鹿上游的实现,依赖"裁判系统给的最大功率"与"超电给的能量缓冲"。我们裁判系统已联通(RM-005),
但**0x0202 的功率字段没解析** → 输入缺失。所以这不是调参,是补链路。

### 3.2 速度估计空实现,导致三件事都做不了

`EstimateSpeed()` 只有一行注释。没有它:①打滑无从判断;②功率模型里的 Σ(τω) 只能拿**指令速度**算
(打滑时严重失真);③里程/定位做不了。**它是功率控制与滑移补偿的公共前置。**

### 3.3 小陀螺平移偏置是"经验补偿",不是"滑移补偿"

现有 +10° 固定偏置(DEV-20261103-03)把"正转向右微漂"压住了,但它是**单一工作点**拟合出来的常数:
自转速度、地面摩擦、电池电压一变就会漂。升级方向是用 P1 的估计速度算出**实际滑移率**,再按滑移率
动态修正平移方向(或直接对四轮做滑移补偿),而不是猜一个角度。

### 3.4 几何量刚修正,必须用速度估计反向验证

力臂 212→340mm 是纸面换算,`CHASSIS_ROTATE_SPEED=300` 现在到底跑多少度,**没有实测过**。
P1 的逆解速度正好可以拿来交叉验证(轮速逆解 wz vs **yaw 关节转速取反**,见 P1-V3 的说明)。

### P2 功率控制基础版(≈1.5 小时)

**先定实现层级(原计划没写,是开工阻塞点)**

底盘侧只有**轮速指令**(`chassis.c` 里 `DJIMotorSetRef(motor_lf, vt_lf)` 给的是速度环目标),
真正的"目标电流"在 `DJIMotorControl` 内部由速度环产生。所以"四轮电流同比例缩放"有两条落点:

| 落点 | 做法 | 代价 / 特性 |
|---|---|---|
| **L1 指令层(推荐先做)** | 在 `chassis.c` 把 `vt_lf..vt_rb` 乘以 `scale` 后再下发 | 只改 chassis.c,不动模块;严格说这是"缩轮速",打滑/非线性下功率不精确,但与方案 A 同族,四轮协调天然保持 |
| **L2 输出层** | 在 `DJIMotorControl` 写 `tx_buff` 前按 `power_scale` 缩放底盘分组 | 更贴方案 B、功率利用率更高,但**是模块级改动**(需按分组白名单,避免误伤云台/发射),对应 DEV 条目须写明波及面 |

**本计划:先 L1(低风险、当天可测),L1 实测走直线不达标再上 L2。**

**步骤**

1. 功率来源(2027 手册定案后改写):**裁判不给功率**——0x0202 的电压/电流/功率是保留位,只有 `buffer_energy`,
   且**10Hz**。所以必须**自建估算**:`P ≈ Σ(τω) + K1Σ(τ²) + K2Σ(ω²) + K3`(电机功率模型,**这就把原 P3 变成必需项**),
   用 `buffer_energy` 的慢变化(dE/dt)做**低频校正**。10Hz 采样决定了**功率环带宽只有几 Hz**,
   快速超功率只能靠模型前馈挡住,不能靠反馈救;
2. 若 `P > P_limit`:`scale = clamp(P_limit / P, 0.3, 1.0)`(只缩不放,且设下限防止缩到停转);
3. `P_limit` 来源:裁判 0x0201 的 `chassis_power_limit`,**收到 0x0201 时刷新**(`robot_level` 变化会改这个值,
   不能只在初始化读一次);数据超时/异常时 **fallback 80W**(RM 圆桌明确建议);
4. 记录缩放比与触发次数,判断是不是长期贴限幅跑。

| 判据 | 目标 |
|---|---|
| 不触发断电 | 连续大功率机动 60s 内 `buffer_energy` 不归零 |
| 走直线 | 缩放下直行 3m 偏移 < 10cm(L1 的主要风险) |
| 功率利用率 | 平均 P/P_limit > 0.85(不保守浪费) |
| **估算精度** | 模型估算的 P 与 `buffer_energy` 长期趋势一致(±20% 内),否则先修模型再谈限幅 |

**回退**:`CHASSIS_POWER_LIMIT_EN=0`,恢复无功率控制。

### P3 电机功率模型(**由"可选"升为必需**,≈2 小时)

2027 手册确认裁判不提供功率,模型成为 P2 的输入而非补充。用 (τ, ω) 与实测功率(由 `buffer_energy` 斜率折算)
拟合 `P = Σ(τω) + K1·Σ(τ²) + K2·Σ(ω²) + K3`(Daniel-sjy 形式);**R² > 0.9 才启用**,
否则退回更保守的 `P = Σ(τω)·k` 单参数形式并收紧 `P_limit`。

### P4 缓冲能量 PID + 爆发补偿(≈2 小时,需裁判数据稳定)

1. 缓冲能量 PID:目标 20J,输出修正 `P_limit`(能量高→放开,接近 0→收紧);
2. 爆发补偿:仅当 `buffer_energy > 阈值` 时允许短时超功率(参考 120W 上限,按鲁棒性下调);
3. 判据:缓冲能量长期维持在 15~25J,不出现"冲一下就没电"。

### P5 滑移补偿升级(≈1.5 小时)

1. 用 P1 的滑移率基线,把固定 +10° 偏置换成分段修正:滑移率 → 平移方向补偿角(查表或线性拟合);
2. 若滑移随自转速度单调,直接拟合成 `bias = k × |wz|`;
3. 判据:小陀螺 100/200/300 三档直行 3m,横向漂移都 < 10cm(现在只有单点 10° 偏置,高档必然偏)。

**回退**:恢复固定 `CHASSIS_TRANSLATE_BIAS_ANGLE`。

### P6 上限与斜坡重标(≈1 小时)

1. 6000 RPM 限幅:小陀螺 + 平移叠加,看是否削顶(削顶=机动性损失);
2. `CHASSIS_VX/VY_RAMP=5000 mm/s²`:按"起步是否打滑/是否窜"双向试(4000/6000);
3. `CHASSIS_ROTATE_SPEED`:几何修正后重新体感(见 P1-V3)。
