## 0. 一句话结论

平移链在**单位换算、四轮等比例限幅、逆解估计、断流保护**四项上已超上游 baseline;
真正的差距只剩三处,且三处有依赖顺序:

```
指令矢量归一化(D1)  →  功率限制(D2)  →  小陀螺漂移补偿 ω 化(D3)
```

D1 是纯手感/一致性缺陷,改动最小;D2 是结构级变更(新增模块 + 改调用链),按 `AGENTS.md` 须单批批准;
D3 的标定必须在 D2 之后做,否则要标两遍(理由见 §5.3)。

## 2. 本工程现状链

```
cmd_remote / cmd_kbm           vx,vy (mm/s, 云台系)
   ↓ chassis_cmd → pubsub(200Hz)
小陀螺偏置旋转(仅 ROTATE)      CHASSIS_TRANSLATE_BIAS_ANGLE = 10°
   ↓
斜坡                           CHASSIS_VX/VY_RAMP = 5000 mm/s²(wz 刻意不加)
   ↓
云台系→底盘系(按 offset_angle 旋转 −θ)
   ↓
45° 全向轮正解                ×0.7071×WHEEL_RATIO(≈14.52 deg/s per mm/s)
   ↓
四轮等比例限幅                CHASSIS_MAX_MOTOR_RPM 6000 → 36000 deg/s(转子)
   ↓
DJIMotorSetRef → M3508 速度环(Kp 0.75 / Ki 1.0,反馈 deg/s)
```

代码位置:

| 段 | 位置 |
|---|---|
| 遥控输入与死区迟滞 | `application/cmd/cmd_remote.c:114-130` |
| 键鼠输入 | `application/cmd/cmd_kbm.c:88-97` |
| 命令结构体与坐标系约定 | `application/robot_def.h:73-85` |

关键换算(供核对):`WHEEL_RATIO = 360×19/(2π×75) ≈ 14.52`;1500 mm/s 单轴 → `1500×0.7071×14.52 ≈ 15400 deg/s ≈ 2566 RPM`。

## 3. 与上游 baseline 的逐项差分

| 项 | 上游 basic_framework | 本工程 | 判定 |
|---|---|---|---|
| 正解公式 | `±vx±vy±wz·L`,**无 0.7071、无 WHEEL_RATIO**(`chassis.c:151-157`) | 补 `×0.7071×WHEEL_RATIO` | 上游无物理量纲,`vt` 直接当转子角速度;本工程已修 |

| 功率限制 | `SetPowerLimit()` 有调用(`:200`),但 `power_control` 模块**本工程未移植** | 同样空缺(`LimitChassisOutput` 内注明待接入) | 两版都缺 |
| 速度估计 | `EstimateSpeed()` **空函数体**(`:181-186`) | 逆解 + 云台居中静态断言 | 本工程补齐 |
| 跟随律 | `wz = -1.5·off·|off|` 平方律(`:223`) | 线性 KP + FF + AFF + 额度分配 | 本工程更细,见 DEV-20261120-18 / -21-02 |
| 小陀螺 wz | 魔数 `4000`(`:226`,量纲残缺) | `CHASSIS_ROTATE_SPEED 300` 实测 | 本工程已修正 |

**结论**:上游不是"更完整的参考实现",它在单位、限幅、逆解、跟随四项上都是空白或占位。

## 4. 开源做法归纳(仅写能坐实的部分)

### 4.1 运动学公式:同构,差异只在轮序/极性/安装方式

各家写法都是 `wheel = ±vx ±vy ± w·L` 的线性叠加,区别只在:轮序编号、电机正反装、X 型还是 Y 型安装。
可验证的结构性不变量有两条,任何正确实现都满足:

- **对角轮同号**(45° 全向轮/麦轮 X 型);
- **旋转项四轮同号**(45° 全向轮的特征;麦轮是左右两组反号)。

本工程正解满足这两条。`[源码 已读]`
上游的 `LF/RF/LB/RB` 命名与物理位置在差分上表现为"哪一对对角取正",属安装差异,不构成错误。

### 4.2 指令归一化:行业共识,而我们只做了一半

二手文章给的标准流程(与 §5.1 的问题直接对应):推满 `Vx=Vy=Max` 时某轮需要 `2×Max`,物理上跑不动就破坏
四轮比例、轨迹形变;解法是找四轮计算值的最大者,按 `K = V_limit / V_max_calc` 整体缩放。`[二手]`

本工程确实做了这个缩放,但**上限取的是电机 6000 RPM,而不是 `CHASSIS_MAX_SPEED`**,见 §5.1。

### 4.3 功率限制:两条成熟路线

**路线 A — 六项式拟合(304 战队,RM2026 开源)** `[作者自述]`

```
W = K0 + K1·I + K2·ω + K3·I·ω + K4·I² + K5·ω²
```

- 给出实测 M3508 参数:`K0=0.65213, K1=-0.15659, K2=0.00041660, K3=0.00235415, K4=0.20022, K5=1.08e-7`,
  电流换算比 1000(即代入模型的电流是"反馈值/1000",不是原始码)。
- 超限时解二次方程求 `0~1` 的衰减系数,乘在**即将发送的电流**上;有效解取较大者,无解则降为 0。
- 功率分配:按各电机 `error`(= 目标速度 − 反馈速度)占比分配,并给每台电机保底功率(电调自身有静态功耗)。
- 作者自述"26 赛季 RMUL 部署后未出现明显超功率"。

**路线 B — 三参数 + 在线辨识(港科大 ENTERPRIZE,RM2024)** `[二手]`

```
P = k1|ω|·τ + k2·τ² + k3/n     (k1≈0.22 W/(rad/s), k2≈1.2 W/(N·m)², k3≈2.78 W)
```

用 RLS(遗忘因子 0.9999)在线更新 `k1/k2`,预测误差收敛到 5 W 以内;据称整赛季零超功率。
精度更高,但引入矩阵运算与在线辨识,工程量与 RAM 占用都不是一个量级。

**本工程的相关事实**:

- `modules/` 下**没有** power_control 模块(仅上游 assets 里有快照)。
- 功率数据链路已具备:`referee_protocol.h:204-207` 已按官方协议解析
  `chassis_voltage / chassis_current / chassis_power(float)`(2026-11-20 由 `reserved3` 更正);
  `chassis.c:213-214` 已在取 `chassis_power` 与 `buffer_energy` 并打 `[chcal] p=/be=`。
- `[待核]` `.Doc/robots/infantry/design/底盘优化计划.md` §1.2 记载"2027 协议确认 0x0202 不含电压/电流/功率,仅 buffer_energy",
  与当前代码注释冲突。**判据**:实车接裁判系统后看 `[chcal] p=` 是否恒 0 / -1;若恒 0 则该说法成立。

### 4.4 小陀螺平移漂移:开源已从"固定角"进化到"随 ω 变化"

304 战队的做法 `[作者自述]`:在底盘解算时给 `theta` 角加**与旋转速度 `rotate` 相关的前馈补偿**。
作者明确写了三点:

1. 推测根因是**功率控制限制了电机输出**,使电机速度变化不再瞬时,行进方向变化存在滞后;
2. 偏移程度至少与当前平移速度、旋转速度、功率上限、平移/旋转速度比有关;
3. 自称"**不是彻底方案**",建议参考河北工业大学开源的全向轮小陀螺补偿方案。

对照本工程:`CHASSIS_TRANSLATE_BIAS_ANGLE = 10°` 是固定角,配置注释也写着"暂定、用户未回报最终效果"。

**注意第 1 点对我们的适用性**:我们目前**没有功率限制**,所以"功率限制导致滞后"这条根因不成立。
我们的漂移更可能来自轮子打滑、几何/力臂误差、重心偏心 —— 根因不同,不能照抄他们的补偿形式。

## 5. 三处差距:现象、改动点、风险

### 5.1 D1 指令矢量未归一化(建议先做)

**现象** `[源码 已读]`

- 键鼠 `W+A` → `vx=1500, vy=1500`;四轮最大 `30800 deg/s ≈ 5134 RPM` < 36000,**不触发限幅**
  → 实际合成速度 `√2×1500 ≈ 2121 mm/s`,比设计上限快 41%。
- 遥控 `vx = MAX·f/√(f²+r²)` 是**恒幅值**归一化:杆量只决定方向、不决定大小,
  即"过死区即满速"。开源主流是比例映射 `MAX·(f−db)/(660−db)`。

**改动点**(二选一或同时):

1. 在 `chassis.c` 斜坡之后,对 `(vx_ramp, vy_ramp)` 做 `k = min(1, CHASSIS_MAX_SPEED/norm)`;
2. 遥控改为比例映射,死区沿用现有 30/20 迟滞。

**风险**:低。只影响极端工况与遥控微操手感,不触碰解算与限幅;
代价是键鼠斜向会变慢(这正是设计意图)。

**判据**:架空推 `W+A`,VOFA 通道 2(`est_vx`)与 5(`est_vy`)应各约 1060,合成 1500;
遥控杆量半推,`vx` 应约为最大值的一半。

### 5.2 D2 功率限制(结构级,须单批批准)

**缺口**:`LimitChassisOutput()` 目前只有转速上限,超功率完全靠操作手。
一旦缓冲能量耗尽 → 裁判断电,是比赛里最硬的失败模式(见 `.Doc/robots/infantry/design/底盘优化计划.md` §0)。

**建议路线**:先做 304 的六项式(路线 A),理由:

- 纯 C、解二次、无矩阵,与本工程现有风格一致;
- 作者已给 M3508 参数,可先跑通再自拟合;
- 插入点明确:`LimitChassisOutput()` 内、`DJIMotorSetRef` 之前做电流/参考缩放。

**须评估的代价**:

- **RAM 已 82.18%**(DEV-20261121-01),新增模块的静态开销必须先算;
- 缩的是轮速参考而非电流(我们只有速度环)时,会引入"指令跟不上"的滞后 —— 304 正好指出这会**加重小陀螺漂移**,
  这就是 D3 必须排在 D2 之后的原因;
- 分配策略("按 error 占比 + 保底")对四轮同构底盘收益有限,首版可先做"整体等比例缩放",分配留二期。

**不建议照搬**:港科大的 RLS 在线辨识(精度收益 <10 W,代价是算力与 RAM),在当前 RAM 水位下不划算。

### 5.3 D3 漂移补偿 ω 化(依赖 D2)

**现状**:固定 10°(`CHASSIS_TRANSLATE_BIAS_ANGLE`),施加在斜坡之前,仅 `CHASSIS_ROTATE` 生效。

**建议**:改成 `bias = k·ω + b` 的一阶形式(或按 ω 查表),宏保留一次烧录可试多点的能力。
但**必须先完成 D2 并复测漂移**,因为:

- 若 D2 的缩放改变轮速跟踪,同一 `bias` 角的最优值会整体平移;
- 我们当前没有功率限制,漂移根因与 304 不同(§4.4),先测"纯自转 + 纯平移"两组的实际轨迹再定模型形式。

**判据**:架空无法验(打滑才产生漂移),须落地实测:定速自转 + 定速平移,用 VOFA 通道 2/5 积分对比
理论位移,量出偏角随 ω、随 v 的变化趋势,再决定是常数、线性还是查表。
