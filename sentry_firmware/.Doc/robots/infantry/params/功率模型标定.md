# 功率模型标定(操作手册)

> 目标:把 `chassis_power.c` 的 M3508 六项模型 `K0..K5` 从"304 车参考值"换成
> "本车实测值",预测误差从 ±10W 降到 ±2~3W。
>
> 预计:一次完整标定约 60~90 分钟(10~12 个稳态点 + 拟合 + 回填验证)。
> 适用:`apps/infantry` 底盘。

## 0. 前置条件

- [ ] 固件已包含 `[pwri]`/`[pwr]` 日志(本仓库 2026-11-26 之后的版本)。
- [ ] 固件已包含运行期变量 `chassis_rotate_speed_deg_s`、`chassis_max_speed_mm_s`、
      `chassis_spin_vary`(手柄标定切匀速用)。
- [ ] 裁判系统在线,客户端能看到**底盘功率**;或台架电源/功率计能读真实功率。
- [ ] 场地:架空台架(推荐)或空旷地面;发射机构断电/空仓;遥控急停在手。
- [ ] 电池电压记录一次(模型没有电压项,尽量在相近电压下采完)。

## 1. 固件准备(一次性,需烧录一次)

改 `config/infantry_2026/config_chassis.h`:

```c
#define CHASSIS_POWER_LIMIT_MAX 200.0f   // 临时:让标定点 s=1(测完恢复 90)
#define CHASSIS_CALIB_LOG 1              // 已有
```

> 为什么不是直接 `CHASSIS_POWER_CTRL_EN=0`:保持模型在跑,`[pwr]` 的 `p` 才有预测值,
> 可以边采边看模型偏差。裁判在线时有效上限 = min(裁判 120, 200) − 5 = **115W**,
> 标定点都在 115W 以下,`s=1`。
> 如果裁判不在线(读不到客户端功率),改用 `CHASSIS_POWER_CTRL_EN 0`,此时 `s=1`
> 但 `[pwr]` 的 `p` 恒 0。

编译并刷新烧录副本:

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1 infantry -Current
```

核对 `firmware/current.txt` 的 `UPDATED`/`SHA256` 与本次构建一致,再烧 `firmware/current.elf`。

## 2. 采集通道(RTT)

日志是 **SEGGER RTT**,不是 UART。两种方式:

**A. 一个 EmberProbe 会话(推荐)**
- 侧边栏同时开 RTT 面板和变量面板:变量面板写速度,RTT 面板看 `[pwri]`/`[pwr]`;
- 每个工况把该段 RTT 文本存成 `log/<工况>.log`(面板复制或“日志另存”)。

**B. 命令行逐点录**
- 先关掉 EmberProbe/Ozone(探针只能一个占用);
- 每个工况:`python tools/rtt_log.py --from-boot`,跑 10s 后 Ctrl-C;
- 文件落在 `log/<时间戳>.log`。

> 也可以直接让我用 `mcu-rtt`/`mcu-variables` 采:我写变量、读 RTT、生成 CSV,
> 你只负责读客户端功率和保证场地安全。

## 3. 输入方式(键鼠 / 手柄)

先确认你走哪条输入路径;标定用的稳态点两种都行。

**键鼠(图传)**:Q 开/关小陀螺,C 切 `CONST`,W/A/S/D 平移。

**手柄(遥控/DBUS)**:
- 右拨杆:**向下=小陀螺**,回中=跟随/无跟随,向上=急停;
- 右摇杆:平移;左摇杆:云台;
- 左拨杆:**向下=手动**(标定用),中=自瞄,上=急停;
- 拨轮:扳机(标定时保持回中)。

手柄没有 C 键,标定前用调试器写 **`chassis_spin_vary = 0`** 切匀速档
(1=变速,0=匀速;写回 1 或重新上电恢复默认)。

## 3.1 工况表(建议 10~12 点)

| # | 工况 | 键鼠 | 手柄 | 写入变量 |
|---|---|---|---|---|
| 1 | 静止 | 不操作 | 右拨杆中、摇杆回中、左拨杆下 | — |
| 2 | 匀速 200 | Q 开、C 切 CONST | 写 `chassis_spin_vary=0`,右拨杆向下 | `chassis_rotate_speed_deg_s=200` |
| 3 | 匀速 250 | 同上 | 同上 | 250 |
| 4 | 匀速 300 | 同上 | 同上 | 300 |
| 5 | 匀速 350 | 同上 | 同上 | 350 |
| 6 | 匀速 390 | 同上 | 同上 | 390 |
| 7 | 平移 500 | 按住 W | 右拨杆中、右摇杆推到底 | `chassis_max_speed_mm_s=500` |
| 8 | 平移 1000 | 按住 W | 同上 | 1000 |
| 9 | 平移 1500 | 按住 W | 同上 | 1500 |
| 10 | 组合 300+1000 | Q/C + 按住 W | 右拨杆下 + 右摇杆推到底 | 两个都写 |
| 11 | 组合 390+500 | Q/C + 按住 W | 同上 | 两个都写 |
| 12 | 横移 1000 | 按住 A 或 D | 右拨杆中、右摇杆左右推到底 | 1000 |

每个点保持 **8~10s 稳态**;起步 1~2s 不要,脚本默认只取最后 50%。
每个点结束把右拨杆回中(或松开 W),等 1~2s 再采下一个。

## 4. 每个工况的操作

1. **写变量**:EmberProbe 变量面板/`mcu-variables` 写
   `chassis_rotate_speed_deg_s`、`chassis_max_speed_mm_s`;
   手柄标定第一次先写 `chassis_spin_vary=0`。运行中写单个对齐标量是原子的。
2. **进稳态**:按上表操作,等 1~2s 稳定。
3. **读真实功率**:看客户端底盘功率,记下稳态值(有波动取中间值)。
4. **存日志**:让 RTT 记录 8~10s,存成 `log/<工况>.log`。
5. **转 CSV**:

```powershell
python tools/rtt_pwr_to_csv.py log/300dps.log --power 84.6 --append steady.csv
```

脚本会取最后 50% 样本平均 `i/w`、检查 `s` 和 `be`;`s<0.99` 或 `be<10J` 会警告。
`--append` 自动写表头/追加。

6. **检查**:日志里 `i/w` 应基本平稳;若 `w` 在 210~390 之间摆动,说明还在变速档
   (手柄写 `chassis_spin_vary=0`,键鼠按 C 切 CONST)重采。

## 5. 拟合

```powershell
python tools/fit_power_model.py steady.csv
```

判据:

- `R^2 > 0.98`;
- `max|err| < 3W`;
- 残差最大的点不要集中在同一工况(否则补该段样本)。

工具会输出 `CHASSIS_POWER_MODEL_K0..K5` 的 C 宏。

## 6. 回填与验证

1. 把 K0..K5 填进 `config/infantry_2026/config_chassis.h`;
2. **恢复** `CHASSIS_POWER_LIMIT_MAX 90.0f`;
3. 重新编译烧录;
4. 留 2~3 个没参与拟合的点做验证(建议 250/300 匀速、1000 平移):
   - 这些点在 85W 以下时 `s=1`,直接比较 `[pwr]` 的 `p` 与客户端功率;
   - 目标误差 < 3W;
   - 高速点(>85W)会被限幅,`s<1`,看实际功率是否守在 85W 附近即可。
5. 验证通过后,把结果记进 `.Doc/robots/infantry/params/参数证据表.md` 的 `CHASSIS_POWER_*` 一节,
   标 `[实测]`:拟合值、R²、max|err|、电池电压、日期。

## 8. 排错

| 现象 | 原因/处理 |
|---|---|
| 没有 `[pwri]` 行 | `CHASSIS_CALIB_LOG=0` 或固件不是新版本;确认烧的是 `firmware/current.elf` |
| `s` 一直 <0.99 | 限幅仍在:确认 `CHASSIS_POWER_LIMIT_MAX=200` 且裁判在线;或改用 `CTRL_EN=0` |
| `w` 在摆动 | 还在变速档;手柄写 `chassis_spin_vary=0`,键鼠按 C 切 `CONST` |
| `be` 快速下降 | 实际功率超过裁判 120W;缩短该点时间,等缓冲回充 |
| `be=-1` / `lim=85` | 裁判未接或未收到 0x0202,缓冲衰减已跳过,属正常;此时客户端也没有功率,改用台架电源/功率计 |
| 拟合 R² 低 | 点集中在同一转速/电流;补不同转速和带负载点 |
| 高速段误差大 | 确认 `w` 是 deg/s 且模型内 /6;仍大则重拟合 K2/K3/K5 |
| 换电池后偏差 | 模型无电压项;记录每次电压,尽量同电压比较 |
