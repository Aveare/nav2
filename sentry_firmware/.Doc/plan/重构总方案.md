## 0. 一句话

车已能上场、四轴参数有实车证据链,所以这次重构的**验收底线是零行为变化**:只搬结构、不搬行为。
"零行为变化"不靠口头承诺,靠 §2 的六道可执行闸门(宏集合逐字节比对、逐符号机器码尺寸、纯搬家行多重集校验、主机测试、审计计数、编译零警告)。

## 1. 边界:这次不做什么

以下每条都是**明确不做**,不是"以后再说"。违反任一条即本次重构失败:

| # | 不做 | 原因 |
|---|---|---|
| N1 | 不改任何任务频率/周期/优先级/栈大小(`robot_task.c` 的 osDelay、栈值) | 时序即行为 |
| N2 | 不改任何 `#define` 数值、类型、单位、注释里的判据 | 参数是实车调出来的,不是重构对象 |
| N3 | 不改消息话题名/字段/`pack(1)` 布局/`_Static_assert` 期望值 | 协议合同,改它=改行为 |
| N4 | 不改控制律、滤波系数、调度公式、调用顺序 | 重构只搬位置 |
| N5 | 不动 `Drivers/`、`Middlewares/`、`Src/`、`Inc/`、`.ioc` | 第三方与生成代码 |
| N6 | 不改 `-flto`/`-Og`/`-Werror` 等编译选项,不切换 `-O` 级别 | 会改变机器码生成,闸门失效 |
| N7 | 不新增任务、不改启动顺序、不引入新的全局状态(拆出的内部头文件里的过渡 extern 除外,见 §4 R3) | 新状态=新行为面 |
| N8 | 不重写注释(仅修正因文件移动而失效的 `.Doc/` 路径) | 注释是调参依据 |
| N9 | 不做"顺手优化":不删逻辑、不合并分支、不修 bug、不改死代码的语义 | 混入优化就无法证明零行为变化 |

> 发现 bug 怎么办:记进 `RM_DEVLOG.md` 问题台账,**不在重构批次里修**,由功能批次单独处理。

## 2. 闸门:零行为变化的可执行定义

每批开工前跑一次基线、收工后跑一次,`tools/refactor_gate.py`(R0 新建)把 G1~G7 打成一张 PASS/FAIL 表。
**任一项 FAIL 则该批不合并、就地回退。**

| 闸 | 内容 | 命令 | 通过判据 |
|---|---|---|---|
| **G1** | 宏集合逐字节一致 | `arm-none-eabi-gcc -E -dM -Iconfig config/robot_infantry_2026.h \| sort > build/gate/macros.txt` 后与基线 `diff` | **差异为 0 行**(当前 557 个宏;含编译器内建宏,同工具链下可比) |
| **G2** | ARM 全量编译 | `cmake -G Ninja -B build && ninja -C build` | 0 error;第一方 0 warning |
| **G3** | 主机测试 | `powershell -ExecutionPolicy Bypass -File tests\run_chassis_tests.ps1` 与 `tests\run_ax650_tests.ps1` | ALL PASS(当前实测 ALL PASS) |
| **G4** | 基线审计 | `python .agents/skills/rm-electrical-dev/scripts/audit_baseline.py --project .` | 计数变化**符合该批声明**(如 R3 新增 4 文件 → Added 38→42);RedFlags 不增加 |
| **G5** | 逐符号机器码尺寸 | `arm-none-eabi-nm -S --defined-only build/basic_framework.elf` 与基线比对 | 所有**既有**符号尺寸完全一致;新增符号只能是该批声明拆出的函数;`arm-none-eabi-size` 的 text/data/bss 与基线一致(`-flto` 下纯搬家应逐字节等价) |
| **G6** | 纯搬家行多重集 | `git diff -U0` 的删除行(去空白/去预处理行)与新增行做多重集比较 | 多重集相等 = 只有"移动",没有"改写" |
| **G7** | 记录 | `RM_DEVLOG.md` 新增 DEV 条目(注明 AI 模型名)+ 回退点 | 条目存在,含审计计数与未执行项声明 |

**G5 的边界**:若某批确实需要新增跨 TU 调用(static 变 extern),该符号可能失去内联机会 → 尺寸变化。
此时**允许**在原 ELF 尺寸上浮 ≤0.2% 且必须在 DEV 条目里逐符号解释;超出即回退改设计。

**诚实声明**:G1~G7 只能证明"结构与数值未变",**不能证明实体行为等价**。
真正关掉这个问题只能靠一次实车回归(用户执行,重构全程至少 1 次,建议在 R4 后)。DEV 条目必须写明"实车未回归"。

**目标**:把三个 Task 里 >100 行的内联块抽成 `static` 函数,块内语句顺序、局部变量、`return` 路径逐字保持。

| 函数 | 行数 | 拟抽块 |
|---|---|---|
| `GimbalTask` | 193 | yaw 目标前馈 / pitch 目标前馈 / pitch 重力前馈 / 两处增益调度 / 模式分发 / 遥测 |
| `ShootTask` | 321 | 摩擦轮互锁 / 连发与热量记账 / 单三发队列机 / 堵转 / 遥测日志 |
| `ChassisTask` | 202 | 模式律(NO_FOLLOW/ALIGN/FOLLOW/ROTATE)/ 斜坡投影 / 反馈发布 |

**为什么高风险**:抽取改变了"谁拥有跨周期时序"(例如堵转累计、`loader_pending` 的更新点),local variable 变成函数参数/文件级状态就可能改变行为。G6(纯搬家)在此**不适用**,只能靠逐块人工复核 + G5 尺寸。
**本批建议先做 1 个文件(建议 `chassis.c`,最小且有 P0 上下文)验证方法论,其余两个再定。**

**验收路径(两条,需用户选)**:
- **A 不补测试**(快):G5 + 逐块复核 + **一次实车回归**才认账。DEV 条目必须写"未实车回归"。
- **B 先补主机测试**(稳):把 `heat_guard`(纯逻辑、无硬件)与 `chassis` 的纯算术函数(正逆解/斜坡/限幅/速度估计)先做成主机测试,再拆。代价约 1 个批次的工作量。

**目标**:切断 `modules → application` 反向依赖;消灭证明为死的路径;把"逻辑层禁触硬件句柄"的条文写清楚。

5. 死路径清理(逐项列清单、逐项 grep 证明零读者后才删):`chassis.c` 的 `#if 0` 超电块、`gimbal.c` 死 VOFA 块与空 include、`heat_guard.h` 两个死 API、`chassis_feedback_data`/`Shoot_Upload_Data_s`(**保留还是删除需用户裁决**:删除=去掉一条恒零的消息,行为不可观测但属于"改结构")。
6. `AGENTS.md` 写明条文解释:Init 时把句柄注入模块配置 = 允许(模板依赖注入);Task 内直接访问句柄/寄存器 = 禁止。

**验收**:G1~G7 + 全仓 include 关系图无 `modules → application`、无环。
**风险**:中。头文件级联改动面大(19 个文件经 `robot_def.h` 传递),但漏改必编译失败,不会静默。
