# NUC—STM32 USB 虚拟串口安全联调顺序

本目录用于验证 NUC 与 STM32 的 USB CDC 虚拟串口。所有脚本固定使用稳定设备路径：

```text
/dev/serial/by-id/usb-YueLuEmbedded_Vision_Comm_port_305E356D3034-if00
```

流程只启动 `sentry_usb_bridge.py`，并固定设置 `enable_drive=false`、`enable_autoaim=false`。它不会发送有效底盘速度或有效自瞄目标，也不会启动 Nav2、雷达或自动决策。

## 按顺序执行

进入目录：

```bash
cd /home/rm/COD导航总目录/07_C板USB通信
```

然后严格按编号运行：

| 顺序 | 脚本 | 目的 | 通过标准 |
|---:|---|---|---|
| 00 | `./00_查看执行顺序.sh` | 查看本文 | 能显示完整步骤 |
| 01 | `./01_检查设备与环境.sh` | 检查串口、ROS 2、pyserial 和端口占用 | 稳定串口存在且空闲 |
| 02 | `./02_启动安全串口桥.sh` | 启动唯一串口所有者 | 节点启动且两项执行使能均关闭 |
| 03 | `./03_确认节点与安全参数.sh` | 再次核对实际运行参数 | `enable_drive=false`、`enable_autoaim=false` |
| 04 | `./04_验证时间同步与大Yaw反馈.sh` | 验证 NV 测时和大 yaw 反馈 | 收到带时间戳的 `big_yaw_joint` |
| 05 | `./05_测量大Yaw反馈频率.sh` | 测量连续反馈 | 输出 `average rate`，协议上限 50 Hz |
| 06 | `./06_检查自瞄RMCV_可选.sh` | 检查可选 `0x1021` | 正式 `sentry` 无数据属于预期结果 |
| 07 | `./07_停止安全串口桥.sh` | 释放串口 | 本套脚本启动的节点退出 |
| 08 | `./08_查看本次结果与日志.sh` | 汇总输出 | 确认没有遗留安全串口桥 |

不要跳过 01、03 和 07。任一步出现 `[FAIL]` 都应先停止，不要继续执行后续步骤。

## 当前固件基线与消息判断

本流程按 2026-11-27 拉取到的 `youyucat/RM-JIT-CR origin/sentry@4c3dfb63` 判断。正式 `sentry` 的 USB CDC 当前接入 4 类 NV 消息：

| 方向 | 消息 | 本流程如何验证 |
|---|---|---|
| NUC → STM32 | `COMMAND=1` | 步骤 02 周期发送 `VALID=0` 零速帧；现行协议没有接收确认帧 |
| STM32 → NUC | `FEEDBACK=2` | 步骤 04、05 检查 `/big_yaw/joint_states` |
| NUC → STM32 | `SYNC_REQUEST=3` | 步骤 04 的带时间戳反馈依赖测时请求 |
| STM32 → NUC | `SYNC_RESPONSE=4` | 步骤 04 的 ROS 时间映射成功即证明响应有效 |

NUC 网关即使关闭自瞄，也会发送 `shoot=0、target_id=0` 的 RMCV 安全空目标；正式 `sentry` 固件不会在 USB 上解析它。远端未合并分支 `feat/sentry/autoaim-nav-power-youyucat` 才接入：

- STM32 → NUC：RMCV `0x1021` 姿态。
- NUC → STM32：RMCV `0x0503` 自瞄目标。

因此步骤 06 在正式分支固件下超时是预期结果，不应把它误判为 NV 导航通信失败。

## 本机部署验证结果

2026-11-27 在当前 NUC 与已连接 STM32 上完整执行 01～08，得到：

- `/big_yaw/joint_states` 约为 `50.0 Hz`，证明 NV 测时响应和大 yaw 反馈有效。
- 收到 `/autoaim/pose`，证明当前实际烧录固件已接入 RMCV `0x1021`；它不是正式 `sentry@4c3dfb63` 的纯 NV 行为。
- 实测姿态帧中的 `projectile_speed=0、robot_id=0`，这两个裁判字段仍未提供有效值。
- 全流程始终保持 `enable_drive=false、enable_autoaim=false`，结束后串口桥已停止并释放端口。

这里只能确认当前烧录固件的链路行为，不能仅凭消息反推出准确 Git commit。更换或重新烧录 STM32 后应重新执行全部步骤。

## 安全边界

- 本流程不验证底盘实际接管，因为 `COMMAND` 没有确认帧，并且主动保持 `enable_drive=false`。
- 本流程不发布 `/cmd_vel`、`/Odometry` 或 `/autoaim/target`。
- 不要同时运行旧 `cod_serial`、`COD_Serial`、第二个 `sentry_usb_bridge` 或完整 `nuc_hardware.launch.py`。
- 真正运动前仍需核对 STM32 编译配置、遥控器仲裁、急停、底盘离地和人员净空。
- 结束或中途失败后执行 `07_停止安全串口桥.sh`。
