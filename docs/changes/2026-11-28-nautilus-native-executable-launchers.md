# 修复 Nautilus 双击程序入口

日期：2026-11-28

## 问题

NUC 使用 Ubuntu 22.04 和 Nautilus 42.6。Nautilus 在普通文件夹中会把 `.desktop` 文件交给文本编辑器打开，即使文件具有执行权限并设置了可信元数据，也无法满足双击直接运行的现场需求。

## 修改

- 新增原生 C 启动器 `field_step_launcher.c`。
- 安装时由 NUC 的 GCC 编译为 ELF 可执行文件。
- 在 **建图与中心点** 文件夹生成 12 个没有扩展名的可执行程序。
- 原 `.desktop` 文件移入带时间戳的隐藏备份目录，不直接删除。
- 原 Shell 脚本继续保存在 `.scripts` 隐藏目录，由可执行程序按固定映射调用。

## 安全边界

启动器只根据自身固定文件名选择对应脚本，不接受外部命令或脚本路径。原有建图与定位安全参数、进程检查和备份逻辑均未改变。

本次不修改 ROS 2 节点、导航参数、串口协议或底盘控制逻辑。
